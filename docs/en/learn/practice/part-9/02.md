# Example 2 · Rollback: Back Out When Something Breaks

> Goal: if you find it broken after going live, you can **quickly roll back to the last working version**, instead of "patching it while it's broken."

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: this exercise corresponds to **[Main Line Part 9](/en/learn/part-9/01)** — read the main-line concepts first, then get hands-on.

## L1 Version Rollback: A Usable Backup {#sec-1}

A Git tag is a "usable-version anchor" — when a version is broken, just switch back to it.

```bash
git tag v0.3.0    # 打标签 = 记下"这版是好的"
# 出问题后：
git checkout v0.2.0   # 切回上一个可用版本
```

> **Key point**: tag before each release, so you know "which version is good and where you can fall back to."

## L2 Rollback Plan: Decide How to Back Out First {#sec-2}

**Think about "how to back out" before deploying**, rather than panicking after something breaks.

```text
问题：v0.3.0 读取中文路径失败
回滚：切到 v0.2.0 再发布（把 tag 指回上一个可用 commit）
回滚顺序：
  1. 确认坏在 v0.3.0（不在下游）
  2. 把发布指向 v0.2.0
  3. 通知用户你退回了
  4. 再慢慢修，别在坏版本上硬撑
```

> **Rollback is "stopping the loss", not "fixing it".** First roll back to a working version so users can keep going, then calmly fix the bug.

## L3 Rollback Combined with Observability {#sec-3}

Logs and rollback are partners: **logs tell you "where it's broken"**, and rollback helps you **"back out first"**.

```
warn  [v0.3.0] session.create  session=s-1  error=读取中文路径失败
  → 立即回滚到 v0.2.0（用户能继续用）
  → 修复 v0.3.0 的问题后再发 v0.4.0
```

> **Rollback isn't failure** — it's a mature engineering move. **Find the problem → back out → fix it → move forward again** — a healthy rhythm.

## Variant Exercises (apply it) {#sec-4}

1. **Tag v0.2.0** and simulate "breaking something, then backing out."
2. **Write a rollback plan**: when to back out, how, and who to notify.
3. **Use logs to locate**: how to know which version to roll back.

## General pattern: plan how to back out + quick rollback + fix and move on {#sec-5}

**Three rollback principles**: ①**tag** (anchor the working version first); ②**plan first** (decide how to back out before deploying); ③**stop the loss first** (roll back to a working version, then calmly fix). **Rollback is an engineering norm, not failure** — only because you can back out can you boldly move forward.
