# Example 1 · Write a Skill (SKILL.md)

> **Goal**: write a "manual" the system can load and use on demand — a skill. The key is `whenToUse`.

<!-- 双向导航: 回主线 -->
> 📚 **Ground yourself with the main line first**: this exercise maps to **[Main line · Part 3](/en/learn/part-3/01)** — read the main-line concepts first, then build it hands-on.

## L1 A minimal SKILL.md {#sec-1}

```md
---
name: report-writing
description: Turn research results into a structured IMRaD paper.
whenToUse: When the user needs to write a paper, report, or abstract, or requests structured writing.
---

## Steps
1. Confirm the study subject and target journal.
2. Build the skeleton per IMRaD: Introduction / Methods / Results / Discussion.
3. Attach evidence to every conclusion (data, DOI).
```

> **The three frontmatter fields**: `name` (unique identifier) · `description` (one-line explanation) · `whenToUse` (when to load it — **the most important**).

## L2 In practice: write "when to use" clearly {#sec-2}

> Write `whenToUse` too narrowly and it never triggers; too broadly and it loads at random. Write "**which scenario should use it**".

```md
---
name: data-clean
description: 清洗实验数据（去缺失、统一单位、去异常）。
whenToUse: 用户给了一堆原始数据、要求整理成可分析表格时。
---

## Steps
1. 先看数据字段与缺失情况。
2. 去缺失：删或插补（注明方法）。
3. 统一单位、去异常（> 3σ 标出）。
```

## L3 Full version: body structured by "clear / actionable / verifiable" {#sec-3}

```md
## Steps
1. 读取 `data/*.csv`。
2. 检查 `head()` 与缺失率。
3. 缺失率 < 5% 删行；> 5% 用中位数插补。
4. 输出 `data_clean.csv`。

## Acceptance
- [ ] 无缺失
- [ ] 单位统一
- [ ] 异常已标注
```

## Variant exercises (apply it) {#sec-4}

Write a `SKILL.md` for a scenario you know well:
1. **Statistical plotting**: turn your data into "proper scientific figures."
2. **Weekly report**: organize this week's work into a fixed template.
Requirement: frontmatter (name/description/whenToUse) + steps + acceptance.

## General pattern: skill = an on-demand manual {#sec-5}

**A skill is not a prompt** — it is a reusable, versionable capability package loaded via `whenToUse`. Only when `whenToUse` is written clearly will the model use it at the right moment.
