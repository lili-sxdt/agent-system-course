# Example 1 · JSON-RPC and Web Service

> Goal: Turn the Agent into a "service other programs can call" — an HTTP interface + JSON-RPC convention, listening on localhost by default.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: this exercise corresponds to **[Main Line Part 6](/en/learn/part-6/01)** — read the main-track concepts first, then build.

## L1 Spin up an HTTP service + health check {#sec-1}

```ts
import http from 'node:http'

const server = http.createServer((req, res) => {
  if (req.url === '/health') {
    res.writeHead(200, { 'Content-Type': 'application/json' })
    res.end(JSON.stringify({ ok: true }))
  }
})

server.listen(3080, '127.0.0.1', () => console.log('listening on 127.0.0.1:3080'))
```

> **Key point**: the listening port + `/health` health check + **binding to 127.0.0.1 by default (not exposed to the internet)** — a secure default.

## L2 JSON-RPC: request/response pairing {#sec-2}

```ts
// request
{ "jsonrpc": "2.0", "id": 1, "method": "session.send", "params": { "text": "hello" } }
// response
{ "jsonrpc": "2.0", "id": 1, "result": { "ok": true } }
```

> **`id` pairs requests with responses** — concurrent requests won't get mixed up.

Handle a JSON-RPC request:

```ts
async function handle(req: any) {
  const { id, method, params } = req
  try {
    const result = await route(method, params)
    return { jsonrpc: '2.0', id, result }
  } catch (e) {
    return { jsonrpc: '2.0', id, error: { code: -1, message: e.message } }
  }
}
```

## L3 SDK layering: minimal / app / protocol {#sec-3}

| Layer | Purpose |
|---|---|
| `protocol` | Defines the message types and the contract |
| `minimal` | Most minimal client/server |
| `app` | High-level wrapper (ready to use) |

> **Use what you need**: for a quick connect use minimal; for full capability use app.

## Variant exercises (apply it) {#sec-4}

1. **Add a `session.list` method**: return the list of sessions, over JSON-RPC.
2. **Add CORS / auth to the service**: a middleware that only allows local machine access.

## General pattern: define capabilities first, then the interface {#sec-5}

**Capabilities drive the interface**, not the other way around. What you expose externally follows **minimal exposure** (only open the methods you need, each with clear permissions). Listen on localhost by default, and a health check probes "is it alive" at any time.
