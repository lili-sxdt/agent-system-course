# Example 2 · WebSocket Streaming + Front-end Display

> Goal: Push the Agent's **streaming output** (token by token) to the front end in real time, and show the trajectory.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: this exercise corresponds to **[Main Line Part 6](/en/learn/part-6/01)** — read the main-track concepts first, then build.

## L1 WebSocket: real-time push {#sec-1}

```ts
// first: npm i ws   (WebSocket is a third-party package, needs installing)
import { WebSocketServer } from 'ws'

const wss = new WebSocketServer({ port: 3081 })
wss.on('connection', (ws) => {
  ws.send(JSON.stringify({ type: 'hello' }))
  // push a line of model output
  ws.send(JSON.stringify({ type: 'token', content: 'you' }))
})
```

> **WebSocket = a two-way channel that stays open**, so the server can push proactively (streaming output, tool progress); HTTP request/response only does one-shot requests.

## L2 A small front end: message stream + trajectory {#sec-2}

> UI principles: **get chat working first, then make it pretty**; **trajectory collapsed by default, expand when needed** (debugging + building trust).

```html
<pre id="trajectory" hidden></pre>
<ul id="messages"></ul>
<input id="input" />
<button id="send">Send</button>

<script>
  const ws = new WebSocket('ws://127.0.0.1:3081')
  const input = document.getElementById('input')
  const traj = document.getElementById('trajectory')

  function show(m) { document.getElementById('messages').innerHTML += `<li>${m}</li>` }
  function send() {
    ws.send(JSON.stringify({ type: 'user', content: input.value }))
    input.value = ''
  }
  document.getElementById('send').addEventListener('click', send)
  input.addEventListener('keydown', (e) => { if (e.key === 'Enter') send() })

  ws.onmessage = (e) => {
    const d = JSON.parse(e.data)
    if (d.type === 'token') show(d.content)          // streaming
    else if (d.type === 'trace') traj.textContent += '\n' + d.content  // trajectory, hidden by default
  }
</script>
```

> **Trajectory visualization**: fold tool calls into "cards" (expandable to see params/results), displayed in order.

## L3 Watching the trajectory (the first debugging tool) {#sec-3}

```
▶ call read_file(path: "config.json")
  ✓ returned: { "port": 8080 }
▶ call run_python(...)
  ✓ returned: analysis complete
```

> Being able to read the trajectory lets you tell whether it **took a detour / picked the wrong tool / didn't stop when it should** — this is the first tool for diagnosing Agent problems.

## Variant exercises (apply it) {#sec-4}

1. **Render streaming to the front end**: append token by token as the model outputs them.
2. **Collapse the trajectory**: hidden by default, click to reveal tool calls and results.

## General pattern: stream with WS, show with the trajectory {#sec-5}

**Streaming output** uses WebSocket (can push); simple one-shot requests use HTTP — don't over-engineer. **Collapsed by default, expand when needed**: it neither over-interferes nor prevents you from verifying at any time.
