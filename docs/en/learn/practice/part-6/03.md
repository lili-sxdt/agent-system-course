# Example 3 · Command-line Entry (CLI)

> Goal: Make the Agent usable in terminals, scripts, and pipelines — an **executable command** that supports `--help`, `--json`, and can run in CI.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: this exercise corresponds to **[Main Line Part 6](/en/learn/part-6/01)** — read the main-track concepts first, then build.

## L1 A minimal CLI {#sec-1}

```js
// cli.ts
import { runAgent } from './agent'

const task = process.argv.slice(2).join(' ')   // take the command-line args
runAgent(task).then(console.log)
```

```bash
my-agent "read the title of the README"     # run a task with one command
```

## L2 Subcommands + arguments {#sec-2}

| Subcommand | Purpose |
|---|---|
| `run <task>` | Run a task |
| `session list/new/rm` | Manage sessions |
| `skill list/install` | Manage skills |
| `config get/set` | Configuration |

> **Argument principles**: `--help` always works (self-documenting); sensible defaults; clear error messages.

```bash
my-agent --help
my-agent config get port
my-agent run --json "organize the data"     # output readable by programs
```

## L3 Going into CI: non-interactive + exit codes + parseable {#sec-3}

```ts
async function main() {
  const task = process.argv.slice(2).join(' ')   // same as L1: join the remaining args into one task
  try {
    const r = await runAgent(task)
    console.log(JSON.stringify({ ok: true, result: r }))   // parseable
    process.exit(0)                                        // success → 0
  } catch (e) {
    console.error(JSON.stringify({ ok: false, error: e.message }))
    process.exit(1)                                        // failure → non-zero
  }
}
// non-interactive: never "block waiting for input"
```

> **Being runnable in CI** = the dividing line between "for humans" and "for systems". Requirements: proper exit codes, non-interactive, parseable output, re-entrant.

## Variant exercises (apply it) {#sec-4}

1. **Add `--help`**: list the subcommands and usage.
2. **Add `--json`**: output JSON for easy script handling.

## General pattern: a CLI should be "usable by humans, callable by programs" {#sec-5}

**The CLI is the entry point for scripting/automation**; output is both for humans (formatted) and for programs (`--json`); to enter CI it must be **non-interactive + exit codes + parseable + re-entrant**.
