# Example 2 · Write a File-Reading Tool

> Goal: give the Agent "hands". From the minimal (L1) → add validation/errors (L2) → complete and testable (L3), using the N-D-P-H pattern.

<!-- 双向导航: 回主线 -->
> 📚 **Start from the main line**: this exercise corresponds to **[Main Line, Part 1](/en/learn/part-1/01)** — read the main-line concepts first, then get hands-on.

## L1 Minimal runnable (a tool = four parts) {#sec-1}

```ts
import { defineTool } from './tool'   // scaffold：见主线第3章 defineTool

export const readFileTool = defineTool({
  name: 'read_file',
  description: '读取指定路径的文件内容。',
  parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
  async handler({ path }) {
    const fs = await import('fs/promises')
    return { ok: true, content: await fs.readFile(path, 'utf8') }
  },
})
```

## L2 In practice: validation + error handling {#sec-2}

> A tool isn't guaranteed to succeed — the file may not exist, the arguments may be invalid. **Return failures cleanly** too; don't let it crash.

```ts
export const readFileTool = defineTool({
  name: 'read_file',
  description: '读取指定路径文件内容；文件不存在返回错误。',
  parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
  async handler({ path }) {
    if (!path || typeof path !== 'string') {
      return { ok: false, error: '缺少有效的 path' }
    }
    try {
      const fs = await import('fs/promises')
      return { ok: true, content: await fs.readFile(path, 'utf8') }
    } catch (e: any) {
      return { ok: false, error: `read failed: ${e.message}` }
    }
  },
})
```

## L3 Complete: write tests for the tool (vitest) {#sec-3}

```ts
import { expect, test } from 'vitest'
import path from 'node:path'
import os from 'node:os'

test('正常目录：返回内容', async () => {
  const r = await readFileTool.handler({ path: 'README.md' })
  expect(r.ok).toBe(true)
  expect(typeof r.content).toBe('string')
})

test('不存在文件：返回错误而不抛', async () => {
  const r = await readFileTool.handler({ path: path.join(os.tmpdir(), 'no-such-' + Date.now()) })
  expect(r.ok).toBe(false)
  expect(typeof r.error).toBe('string')
})
```

## Variant exercises (apply it) {#sec-4}

Following this pattern, write a new tool:
1. **list_files**: list the file names in a directory (`fs.readdir`).
2. **count_words**: count the words in a block of text.

Requirements: a full N-D-P-H + validation/error handling + one test each.

## General pattern: N-D-P-H {#sec-5}

**N**ame → **D**escription (when to use) → **P**arameters (parameter schema) → **H**andler (the handling function). Four parts together = one tool. Write the description clearly around "when to use it", and the model will use it correctly.
