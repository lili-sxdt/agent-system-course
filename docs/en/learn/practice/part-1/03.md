# Example 3 · Run a Complete Agent End-to-End

> Goal: chain context + model + tools + loop into an Agent that **actually gets work done**. Watch it "think → call a tool → see the result → think again".

<!-- 双向导航: 回主线 -->
> 📚 **Start from the main line**: this exercise corresponds to **[Main Line, Part 1](/en/learn/part-1/01)** — read the main-line concepts first, then get hands-on.

## L1 Minimal loop (the skeleton) {#sec-1}

> Note: `chat(messages, { tools })` needs an "extended chat" (one that accepts `tools` and forwards it to the model) — take Example 1's `chat()` and add a `tools` parameter.

```ts
const MAX_STEPS = 10
const messages = [{ role: 'system', content: '需要文件内容时用 read_file 工具。' }, { role: 'user', content: '读 README 的标题' }]

for (let step = 0; step < MAX_STEPS; step++) {
  const msg = await chat(messages, { tools })   // tools = 工具列表
  messages.push(msg)
  if (!msg.tool_calls?.length) { console.log(msg.content); break }   // 收尾
  for (const call of msg.tool_calls) {
    const result = await runTool(call.function.name, JSON.parse(call.function.arguments))
    messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(result) })
  }
}
```

## L2 In practice: print the trace + catch errors {#sec-2}

> **Reading the trace** (what each step is doing) is the first debugging tool; a failed tool call should "return cleanly".

```ts
console.log(`[step ${step}] ${msg.tool_calls ? 'call ' + msg.tool_calls[0].function.name : 'reply'}`)
// 工具失败时 result 是 { ok:false, error }，塞回去让模型调整，而不是崩
```

## L3 Complete: a working runAgent {#sec-3}

```ts
async function runAgent(userTask: string, toolList: any[]) {
  const messages: any[] = [
    { role: 'system', content: '需要文件内容时用 read_file 工具。' },
    { role: 'user', content: userTask },
  ]
  for (let step = 0; step < 20; step++) {
    const msg = await chat(messages, { tools: toolList })
    messages.push(msg)
    console.log(`[step ${step}] ${msg.tool_calls ? 'call ' + msg.tool_calls[0].function.name : 'reply'}`)
    if (!msg.tool_calls?.length) return msg.content
    for (const call of msg.tool_calls) {
      const r = await runTool(call.function.name, JSON.parse(call.function.arguments))
      messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(r) })
    }
  }
  return '(reached max steps)'
}

// 跑一个真实任务
runAgent('读一下 package.json，告诉我项目名。', [readFileTool]).then(console.log)
```

**Expected trace**: `[step 0] call read_file` → `[step 1] reply: the project name is xxx`.

## Variant exercises (apply it) {#sec-4}

1. **Add a second tool**: put `listFilesTool` in too, and change the task to "list the directory first, then read one of the files".
2. **Guard against infinite loops**: set `MAX_STEPS` to `3` and run a complex task, then watch how it stops.
3. **Make it multi-step**: change the task to "read a.md and b.md and compare which file has longer lines", and see whether the model reads one per step.

## General pattern: the loop in four steps {#sec-5}

**Think → request a tool → do → push back.** Termination relies on: ① goal reached (no more tool calls), ② step limit (`MAX_STEPS`), ③ error backstop. All three are essential.
