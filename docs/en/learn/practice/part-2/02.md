# Example 2 · Containers and the Registration Mindset

> Goal: learn to "**register with the container**" instead of scattering `new` everywhere. Understand `ctx.plugin / tool / skill / on`.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: This exercise corresponds to **[Main Line Part 2](/en/learn/part-2/01)** — it is recommended that you read the main-line concepts first, then do the hands-on work.

## L1 Mount Plugins with a Container {#sec-1}

```ts
import { Context } from '@deepseek-ai/cordis'

const app = new Context()
app.plugin(myPlugin)          // mount a plugin
app.plugin(myPlugin, { enabled: true })   // with configuration
```

> You only handle "registration"; the container calls them and passes configuration according to the lifecycle.

## L2 Register Capabilities: tool / skill / on {#sec-2}

```ts
export function myPlugin(ctx: Context) {
  ctx.tool(readFileTool)      // register a tool: the Agent can now call it
  ctx.skill(mySkill)          // register a skill: loaded when needed
  ctx.on('ready', () => console.log('ready'))   // subscribe to an event
  ctx.on('dispose', () => console.log('cleaned'))
}
```

> **Key**: after registration, the system **automatically collects** tools/skills into a "available list" during assembly, and hands them to the model. **You only register; the container does the collecting and dispatching.**

## L3 Event-Driven Decoupling {#sec-3}

```ts
// A emits an event
ctx.emit('data:ready', someData)

// B listens (inside another plugin)
ctx.on('data:ready', (data) => console.log('got', data))
```

> **Decoupling**: A does not need to call B directly; as long as A emits an event and B listens for it.

## Variant Exercises (Apply It) {#sec-4}

1. **Write a "counter plugin"**: on load, register some tool; on `dispose`, print "called N times."
2. **Decouple with events**: plugin A `emit`s `'app:started'` on `ready`, and plugin B listens for it to print a log.

## General Pattern: The Registration Mindset {#sec-5}

**Don't `new` yourself; register with the container.** Tools/skills/events are all registered via `ctx.*`; the container is responsible for collecting, dispatching, and lifecycle.
