# Example 3 · Lifecycle and Configuration

> Goal: master the plugin lifecycle (load/init/work/unload) and configuration (default < user < preset).

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: This exercise corresponds to **[Main Line Part 2](/en/learn/part-2/01)** — it is recommended that you read the main-line concepts first, then do the hands-on work.

## L1 Lifecycle Skeleton {#sec-1}

```ts
export function myPlugin(ctx: Context, config: MyConfig) {
  // load: register capabilities
  ctx.tool(readFileTool)

  // ready: initialize
  ctx.on('ready', () => console.log('ready'))

  // unload: clean up (very important)
  ctx.on('dispose', () => console.log('cleaned up'))
}
```

> Four stages: load (register) → ready (init) → running (work) → dispose (cleanup).

## L2 Using dispose to Clean Up Resources {#sec-2}

```ts
export function myPlugin(ctx: Context) {
  const timer = setInterval(() => {}, 1000)
  const conn = openConnection()

  ctx.on('dispose', () => {
    clearInterval(timer)     // ← if you don't clean up, this timer stays alive forever
    conn.close()
  })
}
```

> **The most common beginner mistake**: write only startup, never cleanup. Repeated install/uninstall leaks resources, and the system gets slower and slower or even crashes.

## L3 Configuration: Default < User < Preset {#sec-3}

```ts
const defaultConfig = { enabled: true, pollMs: 5000 }

export function myPlugin(ctx: Context, config = defaultConfig) {
  const final = { ...defaultConfig, ...config }   // default values are overridden by the user config
  console.log('pollMs:', final.pollMs)
}
```

> Priority: **default value < user config < preset/command line**. The more "temporary/specific," the higher the priority. When writing back, pay attention to **atomic writes** (write to a temp file first, then replace) and **validation** (use the default if invalid).

## Variant Exercises (Apply It) {#sec-4}

1. **Add configuration to a plugin**: write a plugin with a config item `interval` (default 5000) that cleans up its timer on unload.
2. **Priority**: the user passes `{ pollMs: 1000 }`, and a preset overrides it on the command line to `pollMs: 0`; what should the final value be?

## General Pattern: Installable and Removable + Configuration Priority {#sec-5}

**"Unload" = unload cleanly** (free all resources); **configuration** is merged by "default < user < preset," and write-back should be validated + atomic.
