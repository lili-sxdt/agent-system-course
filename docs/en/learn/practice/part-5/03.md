# Example 3 · Goal loops and task orchestration

> **Goal**: make the Agent advance itself toward a **persistent goal**, and manage "concurrency / timeout / retry".

## L1 A goal loop {#sec-1}

```ts
interface Goal {
  id: string
  objective: string
  phase: 'active' | 'done' | 'blocked'
  rounds: number
}

async function runGoal(goal: Goal) {
  while (goal.phase === 'active' && goal.rounds < 5) {
    const done = await doOneRound(goal)      // 推进一步
    goal.rounds++
    if (done) { goal.phase = 'done'; break }
  }
  return goal
}
```

> The goal should be **persisted to disk** (made durable), so you can continue after an interruption.

## L2 Determining done / blocked {#sec-2}

```ts
function isBlocked(goal: Goal, rounds: number) {
  // 同一条件连续 N 轮未解，才判阻塞——别一遇困难就喊"卡住了"
  return goal.phase === 'blocked' || rounds >= 3
}

// 完成 = 目标真的达成（有产物、能验收），不是"我尽力了"
```

> **Key point**: "done" is judged by the **goal actually being achieved**; "blocked" is judged only when **the same obstacle persists for N consecutive rounds**.

## L3 Orchestration: timeout / retry (concurrency can be added) {#sec-3}

```ts
function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  return Promise.race([p, new Promise<T>((_, rej) => setTimeout(() => rej(new Error('timeout')), ms))])
}

async function retry<T>(fn: () => Promise<T>, { times = 3, delay = 500 } = {}) {
  for (let i = 1; i <= times; i++) {
    try {
      return await fn()                       // 成功就返回
    } catch (e) {
      if (i === times) throw e                 // 用尽次数，抛最后错误
      await new Promise((r) => setTimeout(r, delay * 2 ** (i - 1)))   // 指数退避
    }
  }
}

async function orchestrate(jobs: any[]) {
  const results: any[] = []
  for (const job of jobs) {
    try {
      results.push(await retry(() => withTimeout(job.run(), 30_000)))  // 30s 超时 + 最多3次重试
    } catch (e) {
      // 不可重试的错误（如参数错误）：记录失败，不中断整体
      console.error('job failed:', e.message)
    }
  }
  return results
}
```

> **Three life-saving mechanisms**: timeout (cut it off if stuck), retry (with a cap + exponential backoff), and error logging (don't break the whole batch). You can also add a concurrency cap (e.g. run `Promise.all` in batches), but here we keep it sequential for stability.

## Variant exercises (apply it) {#sec-4}

1. **Add "resume from checkpoint"**: write the `goal` to disk each round, and read it back to continue after a restart.
2. **Add retry to the orchestration**: for retriable tasks, call `retry(fn, { times: 3, delay: 500 })` (using the `retry` signature above, with exponential backoff).

## General pattern: goal advancement + life-saving mechanisms {#sec-5}

**Goal-driven**: advance **itself** around a persistent goal — done = achieved, blocked = unchanged across consecutive rounds, and resume-from-checkpoint relies on persistence. **Orchestration**: cap concurrency, cut off on timeout, and retry with a cap + backoff.
