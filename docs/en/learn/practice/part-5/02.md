# Example 2 · Workflows (Stages and Barriers)

> **Goal**: organize a multi-step process as a **workflow** — one step per stage, with stages synchronized by "barriers".

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: this exercise corresponds to **[Main Line, Part 5](/en/learn/part-5/01)** — read the main-track concepts first, then do the hands-on work.

## L1 Define several stages {#sec-1}

```ts
const stages = [
  { name: 'retrieve', run: () => searchTheWeb('主题') },
  { name: 'filter',   run: (r) => r.filter(x => x.relevant) },
  { name: 'summarize', run: (list) => summarizeAll(list) },
]
```

> **A workflow = you predefine the structure**; each stage can be "one Agent call" or "one tool call", and stages are connected by **input/output contracts**.

## L2 Sequential stages: one finishes before the next {#sec-2}

```ts
async function runWorkflow(stages: any[]) {
  let data: any
  for (const s of stages) {
    data = await s.run(data)     // 有序执行；上一个完成才进下一个
  }
  return data
}
```

> **Sequential execution is the most stable**: each stage's input = the previous stage's output, so errors are easy to locate. The real **"barrier" (waiting for all parallel tasks to finish) is in L3**: that is where `Promise.allSettled` comes in.

## L3 Parallel + merge (allow partial failure) {#sec-3}

```ts
async function parallelStages(tasks: any[]) {
  const results = await Promise.allSettled(tasks.map((t) => t.run()))  // 允许部分失败
  return {
    ok: results.filter((r) => r.status === 'fulfilled').map((r: any) => r.value),
    failed: results.filter((r) => r.status === 'rejected').map((r: any) => r.reason),
  }
}
```

> **Key point**: **allow partial failures** and **record which ones failed** — don't let one bad result ruin the whole batch.

## Variant exercises (apply it) {#sec-4}

1. **Write a "retrieve → summarize → write report" workflow**: three stages, each with its own run function.
2. **Run two substages in parallel**: one checks "background", the other checks "methods", then merge after the barrier.

## General pattern: workflow vs loop {#sec-5}

**Stable process → workflow**; **uncertain path → loop**. With a workflow you set the structure, so it is controllable; with a loop the model charts the path itself, so it is flexible. Don't over-orchestrate (start simple, add complexity as needed).
