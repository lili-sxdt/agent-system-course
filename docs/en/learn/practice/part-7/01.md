# Example 1 · Writing Tests for an Agent

> Goal: An Agent is a "code + tools + model" combination — **every layer needs a test safety net** — otherwise one change breaks everything.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: This exercise corresponds to **[Main Line Part 7](/en/learn/part-7/01)** — read the main-line concepts first, then get your hands dirty.

## L1 Minimal testable: test pure functions first {#sec-1}

Extract the "pure logic" — no IO, no model — and test it first.

```ts
// format.ts —— pure function, no side effects
export function makePrompt(task: string, ctx: string) {
  return `任务：${task}\n上下文：${ctx}`
}

// format.test.ts
import { it, expect } from 'vitest'
import { makePrompt } from './format'

it('拼出提示词', () => {
  expect(makePrompt('读README', '这是正文')).toContain('任务：读README')
})
```

> **Why test pure functions first**: no environment dependence, runs anytime, runs fast.

## L2 Tool layer testing: mock external dependencies {#sec-2}

Tools calling the model / reading files — replace external dependencies with **mocks**, and test only "our own" logic.

```ts
import { test, expect, vi } from 'vitest'
import { readTool } from './tools'

vi.mock('node:fs', () => ({
  readFileSync: vi.fn(() => '假数据')
}))

test('读取文件', () => {
  const r = readTool({ path: 'x.md' })
  expect(r).toContain('假数据')
})
```

## L3 End-to-end: run the whole chain {#sec-3}

Run one minimal task through the full chain (the real model can be swapped for a mock), verifying it **works end to end**.

```ts
// agent.test.ts —— integration test
test('端到端：给定任务 → 返回结果', async () => {
  const result = await runAgent('一句话介绍你自己', { maxSteps: 3 })
  expect(result.length).toBeGreaterThan(0)
})
```

> **Layered view**: unit (fast/precise) → integration (tools + model coordination) → end-to-end (full user experience). **The further along, the slower and more expensive** — so run unit tests routinely, and end-to-end at critical moments.

## Variant exercises (apply it) {#sec-4}

1. **Add "timeout/failure" cases to the tool layer**: what happens if the model dies?
2. **Use `vi.fn()` to count call times**: confirm how many times a tool was called.
3. **Add an end-to-end case that asserts "the user's goal was achieved"**.

## General pattern: layered testing, isolated by boundaries {#sec-5}

**Agent testing = unit (pure functions) + integration (mock externals) + end-to-end (real/substitute model).** The key is **clear boundaries**: what's our own logic (test it), what's an external dependency (mock it). **Don't pile all tests into end-to-end** — it's slow and brittle.
