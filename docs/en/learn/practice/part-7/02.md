# Example 2 · Logs that Speak Human

> Goal: Logs are the "black box" for troubleshooting an Agent. **They should answer "what just happened, and where did it go wrong"** — not a screenful of gibberish.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: This exercise corresponds to **[Main Line Part 7](/en/learn/part-7/01)** — read the main-line concepts first, then get your hands dirty.

## L1 With level + with time {#sec-1}

```ts
export function log(level: 'info' | 'warn' | 'error', msg: string, meta?: object) {
  const line = `[${new Date().toISOString()}] [${level}] ${msg}`
  const extra = meta ? ` ${JSON.stringify(meta)}` : ''
  ;(level === 'error' ? console.error : console.log)(line + extra)
}

log('info', '工具已注册', { count: 3 })
// [2026-08-18T10:00:00.000Z] [info] 工具已注册 {"count":3}
```

> **Levels**: `info` tells the story, `warn` flags something to watch, `error` is only for actual failures — **don't log everything as `info`**, or nobody will be able to spot a problem.

## L2 Structured = machine-searchable {#sec-2}

Log **structured fields**, not just concatenated strings — so logs can be grepped, fed into a logging system, and aggregated.

```ts
interface LogEntry {
  ts: string; level: string; event: string; sessionId: string; ms?: number
}

function emit(e: LogEntry) {
  console.log(JSON.stringify(e))
}

emit({ ts: now(), level: 'info', event: 'session.create', sessionId: 's-123' })
emit({ ts: now(), level: 'info', event: 'tool.call', sessionId: 's-123', ms: 42 })
```

> **Key fields**: `event` (event name), `sessionId` (which session), `ms` (duration) — **use an enum for event names, not free text**.

## L3 Observable: request ID + duration + cost {#sec-3}

```
info  [trace=t-abc] session.create  session=s-1
info  [trace=t-abc] tool.read   path=a.md   ms=3
info  [trace=t-abc] llm.call    tokens=1200 cost=0.012  ms=850
warn  [trace=t-abc] model.retry attempt=1  reason=timeout
info  [trace=t-abc] session.done  steps=4 cost=0.05
```

> **One `trace` per chain**: string together all the events of one Agent run; token and cost are **the numbers you're most likely to care about the next day**.

## Variant exercises (apply it) {#sec-4}

1. **Add a `warn` case**: log one when the model times out and retries.
2. **Filter by `sessionId`**: view the logs of only one session.
3. **Make `log` switchable**: output more detail with `--debug`.

## General pattern: structured + leveled + one trace all the way through {#sec-5}

**Three log essentials**: ① **levels** (info/warn/error); ② **structured** (fields, not free text); ③ **trace chaining** (one ID per run). Template: event first, then agent, then time; **findable, readable, locatable**.
