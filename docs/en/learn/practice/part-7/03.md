# Example 3 · Versioning and Release

> Goal: An Agent system **keeps evolving** — version numbers, change logs, tagging — so "what changed and can it ship" is crystal clear.

<!-- 双向导航: 回主线 -->
> 📚 **Start with the main line first**: This exercise corresponds to **[Main Line Part 7](/en/learn/part-7/01)** — read the main-line concepts first, then get your hands dirty.

## L1 Version number: Semantic Versioning (SemVer) {#sec-1}

Semantic Versioning: `major.minor.patch` — simple rules, machine-readable.

| Bump | When |
|---|---|
| Major `1.0.0 → 2.0.0` | **Incompatible** changes (API changed, breaking) |
| Minor `1.2.0 → 1.3.0` | New features (backward compatible) |
| Patch `1.2.0 → 1.2.1` | Bug fixes (backward compatible) |

> **Why it matters**: users/downstream can tell from the version number whether to **be careful**. Chaotic version numbers = trust collapse.

## L2 CHANGELOG: what changed this time {#sec-2}

Each release, spell out "what changed and who it affects":

```markdown
## [1.3.0] - 2026-08-18
### 新增
- `llm.call` 支持流式返回
### 修复
- 修复中文路径读取失败
### 变更
- `readTool` 默认返回 `utf8`
```

> **Write for the reader**: your downstream will be "users / collaborators / other developers" — write what they care about, not your dev to-do log.

## L3 Release process: tag + usable {#sec-3}

```bash
git tag v0.3.0            # 打版本标签
git push --tags
```

> **Where the version lives**: `package.json`'s `version` + root `CHANGELOG.md`, kept in sync. **Run tests before releasing** — releasing means "this commit is usable".

## Variant exercises (apply it) {#sec-4}

1. **Tag a `v0.3.0`**, write the `CHANGELOG`.
2. **Add a compatibility note**: `v2.0.0` is breaking — how to migrate.
3. **Make tests a release gate**: don't release if tests fail.

## General pattern: SemVer + CHANGELOG + tag, the three-piece set {#sec-5}

**Three version essentials**: ① **Semantic versioning** (major.minor.patch, clear rules); ② **CHANGELOG** (reader-facing change log); ③ **Git tag** (one tag per usable version). Combined with "run tests before releasing", releases earn credibility.
