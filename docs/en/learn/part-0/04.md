# Chapter 4: Learning Map and Final Goal

> This chapter gives you a "map": what exactly we will build, how we will get there step by step, and roughly how hard each stretch is. **Look at the map before setting out, and you will not get lost.**

## 4.1 What the "mini-harness" you will build looks like {#sec-1}

Our final goal is not "use an agent someone else built" but "**build a small agent runtime of your own, by hand.**" We call it **mini-harness**.

It is not merely "runs an example." It has **boundaries** — it should be like DSH:

- **Pluggable**: capabilities split into units you can mount or unmount;
- **Has tools**: a model can invoke them (read files, run commands, etc.);
- **Has memory**: remembers multiple turns, compresses over-long context;
- **Safe and controllable**: knows which operations need user confirmation, does not touch your files carelessly;
- **Publishable**: can be packaged, shared, and iterated through a version.

In one sentence: **what you deliver is a small agent system that "runs, is safe to use, and can be shipped."**

## 4.2 How the chapters assemble it step by step {#sec-2}

We assemble it "from the bottom up," piece by piece:

| Stage | What you are building | Part |
|---|---|---|
| ① Groundwork | context + model + tools + loop (that core "think→act→observe→think" line) | Part 1 |
| ② Skeleton | plugin + container + config (making it organized and pluggable) | Part 2 |
| ③ Capability | write your own skill / tool / persona | Part 3 |
| ④ Growth | session / memory / files / security / approval | Part 4 |
| ⑤ Orchestration | multi-agent / workflows / goal loop | Part 5 |
| ⑥ Productization | interfaces / service / frontend / CLI | Part 6 |
| ⑦ Engineering | structure / tests / logs / versioning / standards | Part 7 |
| ⑧ Capstone | assemble these into a complete mini-harness | Part 8 |
| ⑨ Post-release | ship → feedback → verify → maintain → change → re-release | Part 9 |

**Key**: each step **adds a piece on top of what came before**; Part 8 is "assembly," not "starting from scratch."

## 4.3 The difficulty curve {#sec-3}

- **Early is easy** (Parts 0–1): concepts + minimal runnable, you see things move quickly.
- **Part 3 is the watershed**: you start "really writing things the system recognizes" (skill / tool / persona); this is where people most often get stuck, but it is also where the payoff is greatest.
- **Later is depth**: security, orchestration, productization, engineering — you need some system and engineering foundation.

**In one sentence**: the more you do, the more confident you feel; the middle stretch crosses the "how to write" threshold, and the back end makes it professional. **Do not fear the middle — that is where others and I most want to help you cross.**
