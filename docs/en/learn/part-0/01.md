# Chapter 1: What Is an LLM Agent

> This zero-barrier opening chapter explains, in plain terms, what an agent is, how it differs from an ordinary chatbot, and why simple chat is insufficient for real tasks. After reading it you can form a first-level judgment about any "AI agent" product.

If you have only chatted with chatbots such as ChatGPT, you might assume that AI is simply "you ask, it answers." The agent this course addresses, however, is a different kind of system: **it does not merely answer you — it gets things done.**

## 1.1 An executor that acts {#sec-1}

**In plain terms**: A chatbot is a mouth that only speaks; an agent is an executor that acts. When you give it a task, it does more than talk — it actually does the work: reading files, running programs, looking up information — then hands you the finished result.

For example:

> You tell a chatbot, "Help me turn the data I collected today into a table."
> It can only reply, "Sorry, I can't access your files. You could…"

> You tell an agent the same thing, and it (with a supporting system behind it) actually locates your data file → reads it → analyzes it → generates a table → hands it to you.

**Technical**: An agent is a system that uses a large language model (LLM) as its "brain" and can perceive its environment, invoke tools, decide the next action, and observe the outcome, iterating through a loop until it achieves a goal. It is not a model itself but "a model plus a surrounding layer that enables it to act."

## 1.2 The boundaries of an LLM's abilities {#sec-2}

To understand an agent, you must first know the *limits* of a model — because an agent exists precisely to cover those limits.

**What models do well**: understanding language, reasoning, summarizing, translating, writing code snippets, and answering questions.

**What models do poorly**:
- **Precise computation** (error-prone, especially multi-digit arithmetic);
- **Access to real-time or external data** (they do not know the current time, the weather, or your latest quote);
- **Directly operating on systems and files** (they cannot open a file, change a setting, or run a command for you);
- **Accurate, reliable long-term memory** (as context grows, they "forget" or confuse earlier details).

**For this reason**, a model needs:
- **Tools (hands)** — to do the things a model cannot do on its own;
- **Context (memory)** — to retain what it needs to know.

These two are the core of the next several chapters.

## 1.3 Why "chatting" alone cannot handle real tasks {#sec-3}

Many real tasks are not resolved by a single reply; they are processes with several steps, multiple tools, and dependencies between steps. For example, "convert all the reports in this folder to a unified format" requires listing directories, reading files, modifying content, and writing back — several steps, each depending on the previous result.

A chatbot's question-and-answer exchange ends in one round and cannot support such multi-step processes. An agent, by contrast, uses a loop to repeat "think → act → observe → think again" until the task is done. **That loop is the dividing line between an agent and a chatbot**, and it is the core you will build by hand in this course.

**In one sentence**: a chatbot is "ask and answer"; an agent is "accept a task → execute step by step → deliver a result." The difference lies in **whether it acts, and whether it iterates step by step**.
