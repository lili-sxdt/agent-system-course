# Chapter 2: What Is a Harness / Agent Shell

> The previous chapter described an agent as an executor that acts. But a model and tools alone are not enough — **who** is responsible for tying the "model," the "tools," and the "memory" together and spinning them? This chapter introduces that central piece: the **Harness (shell)**.

## 2.1 The core problem a Harness solves {#sec-1}

**In plain terms**: A model is only a "brain," but by itself it does not know "when to call a tool, how to pass one step's result to the next, or how to remember the whole conversation." You need to build a **workbench** around it — one that schedules the model, connects tools, keeps context, and presents results to you. **That workbench is the Harness.**

**Technical**: A Harness (also called an agent framework, agent runtime, or agent loop) is responsible for orchestrating the closed loop of "**context → LLM → tool → result → back to context**," and for handling peripheral concerns such as sessions, memory, permissions, errors, and timeouts. Simply put: **the model does the thinking; the Harness turns thinking into doing.**

The "scut work" it handles includes:

- deciding **when** to feed a tool result back to the model;
- remembering **multiple turns** (context management);
- how to **recover on failure**, and when to stop on timeout;
- which operations need **user approval** and which are allowed (permissions).

## 2.2 What DSH (DeepSeek Harness) is {#sec-2}

**DSH** = an open-source, **plugin-based** agent runtime released by DeepSeek (a large-model company). It does exactly the "shell work" described above — and does it thoroughly:

- every capability is packaged as a **pluggable module** (a `dsh-*` package) that you can install, remove, or replace;
- internally, a **plugin container** (Cordis) ties them together — which is why it can hold several hundred modules without falling apart;
- it also gives you a **convention for writing your own skills, tools, and personas**, so you can extend it.

**In plain terms**: DSH is like a "**pre-built agent workbench with standard interfaces**." What you need to do is not to rebuild it, but to **understand how it is assembled.**

## 2.3 Shell vs. Kernel {#sec-3}

These two terms are easy to confuse, so let us separate them first:

- **Kernel**: the **core engine that actually runs the agent loop and calls the model** — the "think → act → observe → think again" logic lives here. It is the "engine."
- **Shell**: the **outer interface / program** — responsible for starting the kernel, showing the chat interface, and providing human-clickable things like "open settings / tray / version." It is the "body and dashboard."

**In plain terms**: **the kernel is the engine; the shell is the body and dashboard.** The engine decides how the car runs; the shell lets a person drive and see. DSH's kernel is that loop engine; the desktop program you installed (dsh-desktop) is the shell — it handles display, startup, tray, and interface, while the kernel does the real work.

> This course focuses mainly on **how to build the kernel (the Harness)**; the shell (desktop / interface) is another layer and needs only a passing understanding.
