# Chapter 4: Tool and Task Orchestration

> Once multi-agent/workflow systems run in parallel, a pile of engineering problems appears: who runs first, how long, what happens on failure. This chapter covers **orchestration** — keeping "a crowd of agents" from descending into chaos.

---

## 4.1 Concurrency / timeout / retry {#sec-1}

**In plain terms**: three life-saver mechanisms:

- **concurrency control**: do not launch 100 tasks at once and crush the machine;
- **timeout**: if a task hangs too long, cut it, so it does not drag down the whole system;
- **retry**: automatically retry transient failures (network blips) a few times, rather than giving up on the first failure.

**Technical**:

```ts
// Illustrative: concurrency cap + timeout + retry
const limit = pLimit(4)                       // at most 4 concurrent
const task = () => withTimeout(work(), 30_000) // 30s timeout
await retry(task, { times: 3, backoff: 'exp' })// retry up to 3 times, exponential backoff
```

**Key**: **retries need a cap + backoff**, otherwise "frantic retrying" makes things worse.

---

## 4.2 Scheduling and priority {#sec-2}

**In plain terms**: when there is a lot of work, it queues; **the important stuff goes first.**

**Technical**: **scheduling** decides "who runs first, how many run, and how many resources each uses." **Priority** lets urgent/critical work jump the queue. Common strategies: FIFO, priority queues, fair scheduling.

**Key**: **reserve resources for critical tasks**; do not let a swarm of small tasks starve a big one.

---

## 4.3 Task tracking (jobs) and progress {#sec-3}

**In plain terms**: with a pile of tasks running, you must be able to **see their status** — which is running, which is done, which failed.

**Technical**: **task tracking** gives each task an ID and a status (pending/running/done/failed), and supports **checking progress, viewing output, and cancelling tasks**. This is the basis for the observability of a "multi-task system."

```ts
interface Job {
  id: string
  status: 'pending' | 'running' | 'done' | 'failed' | 'killed'
  progress?: number
  output?: string
}
```

**Key**: **a task must be inspectable and stoppable** — otherwise, if it runs wild, you neither know nor can control it.
