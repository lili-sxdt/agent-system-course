# Chapter 1: Subagents

> A single agent going it alone tends to blow up its context and lose track when it hits a "big job." This chapter covers how to **delegate to a "clone"** — a subagent.

---

## 1.1 Why subagents are needed {#sec-1}

**In plain terms**: a big project one person cannot finish is **handed to a colleague.** The same goes for an agent: the main agent **delegates a big task to a subagent**, which completes it in its own "small office" and hands the result back.

**Technical**: a **subagent** is an agent instance spawned by the main agent with an **independent context**. It brings three benefits:

| Benefit | Description |
|---|---|
| **context isolation** | the subagent's intermediate process does not pollute the main conversation |
| **parallelism** | multiple subagents work on different jobs at once |
| **division of labor** | each does its part (retrieval, writing, review) |

**Key**: a subagent is **not for showing off** — its core value is **keeping "the noise of the intermediate process" out of the main context.**

---

## 1.2 The difference between fork and spawn {#sec-2}

**In plain terms**: there are two ways to spawn a subagent:

- **fork**: the subagent **inherits** the main conversation's context — "go do it, carrying what we've discussed."
- **spawn**: the subagent **starts fresh**, inheriting nothing — "go do it from zero; I'll give you the task description."

**Technical**:

| | fork | spawn |
|---|---|---|
| context | inherits the parent conversation | brand new |
| suited to | tasks needing shared background | independent, clean tasks |
| risk | may inherit bias | may lack background |

> **Important**: **audit / independent-evaluation tasks must use spawn** — an "audit" that inherits context carries bias, which amounts to self-review. This is critical in real projects.

---

## 1.3 Context isolation: not inheriting all memory {#sec-3}

**In plain terms**: a subagent should not see **everything** in the main conversation. Give it **just enough** information.

**Technical**: **context isolation** is the core design of subagents. When spawning, inject only **the task description + necessary background + constraints**, not the entire conversation history. This way:

- the subagent **stays focused**, undisturbed by irrelevant information;
- the main context **does not balloon**;
- sensitive information **does not spread**.

---

## 1.4 Delegating and collecting results (structured return) {#sec-4}

**In plain terms**: delegate **clearly**; collect **structured** — do not let it come back with a rambling story; require a "standard report."

**Technical**: a subagent returns a **structured result** (e.g., JSON: conclusion + evidence + artifact path), which the main agent can integrate. **"Artifacts must be written to disk and the path returned"** — so even if the subagent's context is lost, the work remains.

```ts
// Illustrative: delegate + structured collection
const result = await spawnSubagent({
  task: 'Search hyperspectral studies of potato nitrogen diagnosis from the past three years; output 5 key papers',
  schema: { papers: [{ title: 'string', doi: 'string', why: 'string' }] },
})
```

**Key**: **mark information that is not written to disk** (e.g., "[todo]"), to avoid "the subagent says it did it but left no trace."
