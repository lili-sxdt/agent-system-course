# Chapter 1: Releasing v0.1

> Welcome to Part 9 — **"after it goes out."** You have built v0.1, but it is still on your computer. This chapter **actually ships it**, so others can use it too.

> This part distinguishes **【learn】knowledge you can study** from **【do】actions you must perform yourself.** Shipping can be taught as knowledge; the feel of it you have to walk through yourself.

---

## 1.1 Packaging the artifact {#sec-1}

**In plain terms**: first decide "what you are shipping" — a library that can be `npm install`ed? a command you can double-click? or an installer?

**Technical**: **artifact forms**:

| Form | Suited to |
|---|---|
| **library** | others `import` it in code |
| **CLI executable** | used directly from the command line |
| **installer / container** | delivered to non-technical users |

Key configuration (`package.json`):

```jsonc
{
  "name": "my-agent",
  "version": "0.1.0",
  "bin": { "my-agent": "./dist/cli.js" },   // command entry
  "files": ["dist"],                         // which files to publish
  "exports": { ".": "./dist/index.js" }      // what others import
}
```

---

## 1.2 Publishing to a registry {#sec-2}

> **【do】** This step must be performed by you — it involves your account and credentials.

**In plain terms**: **upload the packaged artifact to npm (or a private registry)**, and others can install it.

**Technical**:

```bash
npm publish                   # publish to npm
npm publish --access public   # public package (first time on a free account)
```

Before publishing, run `npm pack` first to check whether "the files to be published" are correct.

---

## 1.3 Pre-release self-check {#sec-3}

> **【learn + do】** The checklist can teach you, but **actually installing it on another machine** is on you.

- [ ] Verify item by item against the "7 publishability criteria" (Part 8 §4.1);
- [ ] `LICENSE` / `NOTICE` compliance (keep MIT, state the relationship to DSH);
- [ ] **Cross-environment verification on real machines**: another computer, another OS, another Node version.

> **【do】Experience note**: on a genuine first release, **there are always environment problems you did not anticipate** — fine on your machine, but it errors on someone else's. Only a real release reveals them.

---

## Checklist {#sec-4}

- [ ] Can state the three **artifact forms** and their suitable scenarios.
- [ ] Knows what `bin` / `files` / `exports` each control.
- [ ] Can run `npm publish` once (or publish to a private registry).
- [ ] Completed **cross-environment verification on real machines**.

**Follow-up** (look back at §1.1 if stuck): why run `npm pack` for a look before publishing, rather than `npm publish` directly?
