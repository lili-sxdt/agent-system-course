# Chapter 5: Making Changes

> To ship v0.2, you must change code. But "changing" has its craft — **change correctly, change safely, change reversibly.**

---

## 5.1 Locating the problem {#sec-1}

**In plain terms**: **find the root cause first, then apply the remedy.** Do not change things on a hunch.

**Technical**: locating means (Part 7 §3.1):

- **logs**: see the context in which the error occurred;
- **trajectory**: see what the agent does at each step (the first means for integration debugging);
- **bisection**: cut the system/code in half and see which half has the problem.

**Key**: **reproduce first, then locate, then change** — do not reverse the order.

---

## 5.2 Small changes and rollback {#sec-2}

**In plain terms**: **change only a little at a time**; test after each change; revert whenever you can.

**Technical**:

- **small commits**: commit each change separately, for easier revert and localization;
- **branch + PR**: make changes on a branch, review, then merge;
- **revertible**: any change must be one-click revertible to the last good state.

**Key**: **"revertible" is the safety net** — with it, you dare to change boldly.

---

## 5.3 Test protection and quality gate {#sec-3}

**In plain terms**: have tests as a backstop before changing; run the full suite after; merge only after passing the gate.

**Technical**:

- **before**: confirm the relevant tests exist (add them if not);
- **after**: run the **full regression**, not just the part you changed;
- **quality gate**: merge only if lint / test / build all pass.

> **【do】Experience note**: **changing one place breaks another** — only after being burned do you realize how important a "full regression" is.

---

## 5.4 Reproducible environment {#sec-4}

**In plain terms**: guarantee that "someone else can rerun and get the same result."

**Technical**: environment snapshot + random seed + locked dependencies (Part 7 §2.2). **If others can still reproduce after the change**, the change is correct.

---

## Checklist {#sec-5}

- [ ] Can state the **three means** of locating a problem and the order "reproduce before changing."
- [ ] Insists on **small commits + revertibility**.
- [ ] Knows that after a change you must run a **full regression** and pass the **quality gate**.
- [ ] Can guarantee that **others can still reproduce** after the change.

**Follow-up** (look back at §5.3 if stuck): you only changed one tool function. Why run the "full regression" rather than testing only that function?
