# Chapter 2: Testing and Reproducibility

> Whether a system can be trusted depends largely on two things: **are the tests sufficient**, and **can the results be reproduced.** This chapter covers both.

---

## 2.1 Unit / integration tests {#sec-1}

**In plain terms**:

- **unit test**: tests whether "one small part" (e.g., a tool function) is correct;
- **integration test**: tests whether "several parts assembled" are correct (e.g., the whole "read file → analyze → write result" chain).

**Technical**:

| | unit test | integration test |
|---|---|---|
| scope | a single function/module | multi-module collaboration |
| speed | fast | slow |
| purpose | logic correctness | interface/flow correctness |

**Key**: **tests must run automatically and run fast.** A test you cannot run is no test at all.

```ts
test('read_file returns file content', async () => {
  const r = await readFileTool.handler({ path: 'fixture.txt' })
  expect(r.ok).toBe(true)
})
```

---

## 2.2 Random seed / environment snapshot / data snapshot {#sec-2}

**In plain terms**: the same operation gives different results yesterday and today — then you cannot investigate anything. You must **fix the "variables."**

**Technical**:

- **random seed**: fix the randomness so "every run is the same";
- **environment snapshot**: record dependency versions and system info (`package.json` + `package-lock.json`, Node version in `.nvmrc`);
- **data snapshot**: use a fixed dataset, not "real-time data that changes anytime."

**Key**: **reproducible = same input + same environment → same output.** If any link is not fixed, it cannot be reproduced.

---

## 2.3 Reproduction report {#sec-3}

**In plain terms**: write a description that lets **someone else rerun and get the same result.**

**Technical**: a **reproduction report (REPRODUCE.md)** should contain: data sources, scripts, commands, dependency versions, random seeds, an artifact list, and a reproduction checklist.

```md
## Reproduction steps
1. Install dependencies: npm ci
2. Run: npm run reproduce
3. Artifacts are in results/, compare against expected/
```

**Key**: **"someone else can rerun it" is what makes it reproducible**, not "it runs on my machine."

---

## Checklist {#sec-4}

- [ ] Can distinguish **unit tests from integration tests**.
- [ ] Can name the **three things** to fix for reproducibility (seed / environment / data).
- [ ] Can state what a **reproduction report** should contain.
- [ ] Knows that "someone else can rerun it" is the standard for reproducibility.
