# Chapter 2: Turning It into a Service

> Turn the agent from "a program" into "a service" — so others (frontends, scripts, other systems) can connect to it over the network.

---

## 2.1 Stand up a web service {#sec-1}

**In plain terms**: run the agent as a "website backend" that **waits for others to connect** on some port.

**Technical**: expose the interface via an HTTP service. Key points:

- **listen on a port** (e.g., `127.0.0.1:3080`);
- **health check** (`/health` returns ok), so "is it alive" can be probed;
- **listen only on local** (`127.0.0.1`) rather than `0.0.0.0` — **not open to the external network by default**, which is a secure default.

```ts
server.listen(3080, '127.0.0.1', () => console.log('listening on 127.0.0.1:3080'))
```

**Key**: **bind to the loopback interface by default**; exposing it externally requires explicit configuration — **secure defaults matter.**

---

## 2.2 WebSocket: real-time frontend-backend communication {#sec-2}

**In plain terms**: HTTP is "you ask, I answer," one exchange at a time. But an agent works in a **streaming** way (spitting out one token at a time, running tools step by step). This calls for a **always-open, two-way channel** — WebSocket.

**Technical**: **WebSocket** keeps a persistent connection after it is established, and the server can **push proactively** (e.g., streaming output, tool progress). It suits real-time interaction.

```
[frontend] ←WebSocket→ [agent service]  (pushes tokens and tool status in real time)
```

**Key**: use **WebSocket** for streaming output; for simple one-off requests, HTTP is enough — do not over-engineer.

---

## 2.3 Client connection / heartbeat / reuse {#sec-3}

**In plain terms**: connections break, multiply, and duplicate — they must be managed.

**Technical**:

- **heartbeat**: periodically send a small message to confirm the connection is alive, so a break is detected promptly;
- **reuse**: do not rebuild a connection for the same client;
- **reconnect**: reconnect automatically on drop, rather than making the user refresh manually.

**Key**: **a connection is a "living thing"** — it drops and jitters; you need heartbeats and reconnects, and must not assume it is always there.
