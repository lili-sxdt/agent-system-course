# Chapter 1: Protocols and SDKs

> Until now your agent could only "run on its own." From this chapter on, let it be **called by other programs** — which requires an "agreed way of speaking" (a protocol) and a set of "convenient wrappers for others to use" (an SDK).

---

## 1.1 JSON-RPC: a convention for inter-process communication {#sec-1}

**In plain terms**: for two programs to talk, they must **agree on how to speak.** JSON-RPC is a simple convention: you send a "request" (saying which method to call and what arguments), and I return a "response" (result or error).

**Technical**: **JSON-RPC** is a lightweight, JSON-based remote-call protocol. A request carries `method`, `params`, and `id`; a response carries `result` or `error`, matched by the same `id`.

```json
// request
{ "jsonrpc": "2.0", "id": 1, "method": "session.send", "params": { "text": "hello" } }
// response
{ "jsonrpc": "2.0", "id": 1, "result": { "ok": true } }
```

**Key**: **the `id` pairs a "request" with its "response"** — concurrent requests do not get crossed.

---

## 1.2 SDK layers: minimal / app / protocol {#sec-2}

**In plain terms**: an SDK (software development kit) wraps "the underlying protocol" into "convenient functions," so others need not assemble JSON themselves.

**Technical**: DSH's SDK is roughly three layers:

| Layer | Purpose |
|---|---|
| **protocol** | defines message types and the protocol contract |
| **minimal** | the leanest client/server implementation |
| **app** | high-level, application-facing wrappers (ready to use) |

**Key**: **layering is for "use as needed"** — to just connect, use minimal; for full capability, use app.

---

## 1.3 What your system exposes {#sec-3}

**In plain terms**: you must decide clearly — **what can others do with your system?** Send messages? Query sessions? Cancel tasks?

**Technical**: a **public API** should follow **least exposure**: open only the necessary methods, each with clear permissions. Do not dump the internals.

**Experience**: define a **capability list** first, then the interface — **capabilities determine the interface, not the other way around.**
