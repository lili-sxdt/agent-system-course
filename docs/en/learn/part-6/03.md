# Chapter 3: The Frontend

> The service is up, but you cannot expect users to type commands at a blank screen. This chapter covers how to build a **usable, understandable** interface for the agent.

---

## 3.1 A minimal chat interface {#sec-1}

**In plain terms**: the simplest interface has three things: an **input box** (typing), a **message area** (showing the dialogue), and a **send button**. Do not reach for fancy tricks right away.

**Technical**: a minimal usable frontend = **message list + input + send + streaming render**. The tech stack is up to you (React / Vue / vanilla all work); the key is **connecting to the backend and displaying in real time.**

**Key**: **get chatting first, then talk about looks.** The interface is the "shell"; the core capability is in the backend.

---

## 3.2 Session list / message stream / skill panel {#sec-2}

**In plain terms**: once it can chat, add three things that "make the system visible":

| Component | Purpose |
|---|---|
| **session list** | a left column to switch / create / delete sessions |
| **message stream** | the central body, showing the dialogue in time order |
| **skill/tool panel** | shows the current skills and tools, with on/off toggles |

**Technical**: these components expose "system state" to the user, turning the agent from a "black box" into an **observable, controllable** tool.

**Key**: **let the user see "what capabilities the system is using"** — this directly affects trust.

---

## 3.3 Visualizing tool results and the trajectory {#sec-3}

**In plain terms**: when the agent calls tools and takes several steps, the user is often lost. **Show every step** — which tool was called, what arguments, what result.

**Technical**: **trajectory visualization**: collapse tool calls into "cards" (expandable to see arguments/results) and show the thinking steps in order. This is key to **debugging** and **building trust.**

```
▶ call read_file(path: "config.json")
  ✓ returned: { "port": 8080 }
▶ call run_python(...)
  ✓ returned: analysis complete
```

**Key**: **collapsed by default, expand on demand** — neither overly distracting nor unable to be checked.
