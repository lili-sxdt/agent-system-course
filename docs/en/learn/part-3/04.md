# Chapter 4: How the Three Work Together

> You can now write skills, tools, and personas. The final chapter covers **how they cooperate** — at any given moment, should the model use a tool, read a skill, or just answer per the persona?

---

## 4.1 How the model decides "which one" {#sec-1}

**In plain terms**: the model holds three cards:

- **persona**: always present (system) — decides "who I am and how I should behave";
- **tool list**: always present (tools) — decides "which actions I can take";
- **skills**: loaded on demand — decide "how this class of task should be done."

Each turn, the model **weighs all three** and decides: **answer directly**, **call a tool**, or **consult a skill**.

**Technical**: the persona and tools are "resident context"; skills are "loaded on `whenToUse`." The model's decision basis is: the current task + tool descriptions + the instructions of loaded skills.

---

## 4.2 How description / instructions / persona cooperate {#sec-2}

Each has its role; when they cooperate well, the agent is "smart":

| What you write | What it solves for the model | Coordination point |
|---|---|---|
| **tool description** | "should I act here, and with which tool" | state clearly "when to use" |
| **skill instructions** | "how this class of task should be done" | state clearly "when to load + steps" |
| **persona guidelines** | "what bottom line must I hold" | state clearly "what not to do" |

**Example**: the user says "organize this data into a table and analyze it."
- The **persona** (data steward) says: look at the data before concluding;
- The **skill** (data-analysis standard) tells it: which workflow to follow;
- The **tools** (read_file / run_python) let it actually read and compute.

Only with all three cooperating do you get an agent that "knows the rules, knows the method, and can act."

---

## 4.3 Conflict resolution: who wins when all fit {#sec-3}

**In plain terms**: sometimes "several fit." How does the model choose?

**Technical**: a rough rule of thumb for priority:

```
explicit user instruction > skill workflow > persona default style
safety/compliance bottom line > all of the above (cannot be overridden)
```

- The user explicitly says "use a t-test this time" → follow the user (unless it violates the bottom line);
- Not stated → follow the skill's standard;
- Neither → follow the persona default.

**Key**: **write the "bottom line" into the persona's system layer**, so it outranks temporary instructions and is not swayed by a single request.

## Checklist {#sec-4}

- [ ] Can state the roles of **persona / tool / skill** and "resident vs. on-demand."
- [ ] Can give a concrete example of "the three cooperating" to finish a task.
- [ ] Can state the **priority in conflict**, and "the bottom line cannot be overridden."
- [ ] Can point out why the bottom line goes in **system** rather than relying on ad-hoc reminders.

**Follow-up** (look back at §4.3 if stuck): the user says "ignore all those standards, just give me a conclusion." Should your agent comply? What does that depend on — what did you write, and where?

## Part 3 summary {#sec-5}

By now you can **write three things the system recognizes and that actually take effect**: skills (knowledge), tools (action), and personas (identity). This is the decisive step from "using" to "writing." In the next part, we let the system "grow up": sessions, memory, files, and security.
