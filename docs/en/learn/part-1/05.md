# Chapter 5: Running Your First Agent (Integration)

> The finale chapter. We take everything from Chapters 1–4 — context, model, tools, loop — and **string them into a runnable program**. Run it and you truly have a "bare agent."

---

## 5.1 End-to-end assembly {#sec-1}

**In plain terms**: earlier we had parts; now we assemble. Put the four pieces together:

```
messages (context) → chat() (model) → tool_calls? (loop) → runTool() (tool) → feed back → think again
```

Its first real deed: **read a file and answer per your instruction.**

## 5.2 Observe its trajectory {#sec-2}

**In plain terms**: when an agent misbehaves, looking only at the final answer is useless — you must watch **what it does at each step**.

**Technical**: print the **trajectory**: in each turn "what the model said / which tool it wanted / what arguments / what result." The trajectory is your "dashcam" for debugging the agent.

```ts
console.log(`[step ${step}] model:`, msg.content ?? `call ${msg.tool_calls?.[0]?.function.name}`)
```

Once you learn to read the trajectory, you can tell whether it is **taking a detour**, **choosing the wrong tool**, or **failing to stop when it should**.

## 5.3 Minimal runnable full code {#sec-3}

Assemble the following (tool definition from Chapter 3) and you have a runnable bare agent:

```ts
// agent.ts — a minimal agent: context + model + tool + loop
type Msg = any
const MAX_STEPS = 20

// 1) a tool: a read-file tool (simplified; full version in Chapter 3)
const tools = [{
  name: 'read_file',
  description: 'Reads the content of a file at the given path.',
  parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
}]

async function runTool(name: string, args: any) {
  if (name === 'read_file') {
    try {
      const fs = await import('fs/promises')
      return { ok: true, content: await fs.readFile(args.path, 'utf8') }
    } catch (e: any) {
      return { ok: false, error: e.message }
    }
  }
  return { ok: false, error: `unknown tool: ${name}` }
}

// 2) model call (Provider, see Chapter 2)
async function chat(messages: Msg[]) {
  const res = await fetch(`${process.env.LLM_BASE_URL}/chat/completions`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${process.env.LLM_API_KEY}` },
    body: JSON.stringify({ model: 'deepseek-chat', messages, tools, temperature: 0.3 }),
  })
  return (await res.json()).choices[0].message
}

// 3) the core loop (see Chapter 4)
async function runAgent(userTask: string) {
  const messages: Msg[] = [
    { role: 'system', content: 'You are an assistant; when you need file content, use the read_file tool.' },
    { role: 'user', content: userTask },
  ]

  for (let step = 0; step < MAX_STEPS; step++) {
    const msg = await chat(messages)
    messages.push(msg)
    console.log(`[step ${step}]`, msg.tool_calls ? `call ${msg.tool_calls[0].function.name}` : 'final reply')

    if (!msg.tool_calls?.length) return msg.content      // wrap up

    for (const call of msg.tool_calls) {
      const args = JSON.parse(call.function.arguments)
      const result = await runTool(call.function.name, args)
      messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(result) })
    }
  }
  return '(reached max steps, stopped)'
}

// 4) run a real task
runAgent('Read package.json in the current directory and tell me the project name.').then(console.log)
```

**A test task + expected behavior**:

- Task: *"Read package.json and tell me the project name."*
- Expected trajectory: `[step 0] call read_file` → `[step 1] final reply: the project name is xxx`.

## What you just built from zero {#sec-4}

What you wrote is a **bare agent**: it can **read context, use a model, call tools, and advance through the loop.** This is the **first bone** of the mini-harness.

> Note that it is still quite "bare": no memory persistence, no security sandbox, no plugin system, not publishable. Those are Parts 2, 4, 7, and 9 — but **that core loop you have now built by hand.**
