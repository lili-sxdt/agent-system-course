# Chapter 1: Sessions and Persistence

> Your bare agent currently "forgets after chatting" — close the program and everything is gone. This chapter makes it **remember**: introduce "sessions" and **save them.**

---

## 1.1 What a session is {#sec-1}

**In plain terms**: a **session** = one continuous conversation. Like a chat window in a messaging app — everything you say in that window belongs to that session; open a new window and it is a new session.

**Technical**: a session is the **carrier of one interaction's context**, containing message history, a session ID, and metadata (creation time, title, which model, etc.). It is the container that "organizes the context."

```ts
interface Session {
  id: string
  messages: Message[]     // all messages of this conversation
  createdAt: number
  title?: string
}
```

**Key**: a session upgrades "context" from "an array in memory" to "an identifiable, manageable, storable object."

---

## 1.2 Persistence: saving the session {#sec-2}

**In plain terms**: keeping it only in memory means it is gone on close. You must **write it to disk** so it is still there next time.

**Technical**: **persistence** means writing sessions to a storage medium. Two common approaches:

| Approach | Characteristics | Suited to |
|---|---|---|
| **JSONL** | one message per line, append-only, simple | small/medium scale, human-readable |
| **Database** | queryable, good concurrency, structured | large volumes, needs retrieval |

A JSONL example (one message per line, just append):

```jsonl
{"role":"user","content":"Please read config.json"}
{"role":"assistant","content":"Sure"}
{"role":"tool","content":"{\"port\":8080}"}
```

**Key**: **append-only writes** are safer and faster than "rewriting the whole file each time" — add, do not modify.

---

## 1.3 Session recovery {#sec-3}

**In plain terms**: next time you open it, **read the stored messages back** and continue chatting.

**Technical**: **session recovery** = load the message history from storage, rebuild the context, and continue the conversation. Points to note:

- **Message order** must be restored (wrong order = amnesia);
- **Tool results** must be stored too (otherwise, after recovery, the model does not know what the tools returned earlier);
- **Version compatibility**: the storage format may be upgraded, so it must read older formats (Part 9 covers migration).

```ts
// Illustrative: recover from JSONL
const messages = (await fs.readFile('session.jsonl', 'utf8'))
  .split('\n').filter(Boolean).map(line => JSON.parse(line))
```
