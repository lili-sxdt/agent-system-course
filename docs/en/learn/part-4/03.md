# Chapter 3: Filesystem / Workspace

> To get work done, an agent must touch files. But "touching files" is a **high-risk action.** This chapter covers how to give an agent a **safe operating range** and design good file tools.

---

## 3.1 Workspace: which directory the agent works in {#sec-1}

**In plain terms**: do not let the agent roam the whole disk. Give it **one folder** as its "office," and it works inside — that is the **workspace.**

**Technical**: the **workspace** is the **root directory** the agent is authorized to read and write. All file operations resolve paths against it, and anything out of bounds is rejected. It is both the "operating range" and the "security boundary."

```ts
const WORKSPACE = process.env.DSH_PROJECT_DIR ?? process.cwd()
```

**Key**: **define the workspace first, then talk about file operations.** Without a boundary, none of the later security design is possible.

---

## 3.2 Designing file read/write tools {#sec-2}

**In plain terms**: give the agent a few "special-purpose tools" — read, write, list, search, edit. **Every tool must be able to fail and report errors** (Part 3 §2.2).

**Technical**: common file tools and their responsibilities:

| Tool | Purpose | Note |
|---|---|---|
| `read_file` | read content | paginate/truncate large files |
| `write_file` | write content | **atomic write** (temp file + replace) |
| `list_files` | list a directory | limit depth, skip huge directories |
| `search` | search content | regex/keyword, limit the scope |
| `edit` | targeted replacement | exact match, avoid unintended changes |

**Key**: **writes must be atomic** — write a temp file, then replace, to avoid "crashed mid-write, file corrupted."

---

## 3.3 Path safety: only touch what should be touched {#sec-3}

**In plain terms**: the user (or the model) may pass a path that "wants to escape," such as `../../Windows/System32`. **You must block it.**

**Technical**: **path traversal** is one of the most common vulnerabilities. The defense: **resolve the path to an absolute path, then check that it falls inside the workspace.**

```ts
import path from 'node:path'

function safePath(workspace: string, userPath: string) {
  const abs = path.resolve(workspace, userPath)   // resolve to an absolute path
  const rel = path.relative(workspace, abs)        // relative to the workspace
  if (rel.startsWith('..') || path.isAbsolute(rel)) {
    throw new Error('path out of bounds, access denied')
  }
  return abs
}
```

**Key**:
- **Do not judge by string concatenation**; use `path.resolve` + `path.relative`;
- **Symlinks** can also escape; handle them carefully;
- **Reject out-of-bounds outright**; do not "try your best."
