# Chapter 2: Memory and Compaction

> As a session grows longer, context piles up — until it no longer fits, or the model starts "losing focus." This chapter covers how to **slim down** memory.

---

## 2.1 The cost of over-long context {#sec-1}

**In plain terms**: more context is not better. Being too long has three drawbacks:

1. **Expensive**: more tokens means more money;
2. **Slow**: longer processing time;
3. **Dumb**: the model "loses attention" — key information gets buried and it cannot hold the point.

**Technical**: context length is bounded by the **model's window limit**; even below that, being over-long reduces effective attention (the "lost in the middle" phenomenon) and raises both cost and latency.

---

## 2.2 Compaction strategies: summarization and pruning {#sec-2}

**In plain terms**: **summarize** the "wordy history" into a paragraph, or **keep only the key information**, to free up space.

**Technical**: **compaction** commonly uses two tactics:

| Strategy | How | Trade-off |
|---|---|---|
| **summarization** | use the model to condense the first N turns into one paragraph | saves space, but may lose detail |
| **pruning** | delete redundancy, trim tool results, remove duplicates | keeps structure, but must avoid deleting the wrong thing |

```ts
// Illustrative: condense earlier history into one item
const summary = await chat([
  { role: 'system', content: 'Condense the conversation below into key information of no more than 200 words.' },
  { role: 'user', content: oldMessages.map(m => `${m.role}: ${m.content}`).join('\n') },
])
messages = [{ role: 'system', content: `[history summary] ${summary.content}` }, ...recentMessages]
```

**Key**: **after compaction, the agent must be able to "keep working"** — the summary must retain "the task goal, what is done, what is pending, and key conclusions," not just pleasantries.

---

## 2.3 Layered memory: recent vs. long-term {#sec-3}

**In plain terms**: like a person — **recent things are remembered in detail; distant things as key points.**

**Technical**: **layered memory**:
- **short-term (recent turns)**: kept in full, to preserve coherence;
- **long-term (earlier)**: compressed into a summary or stored in an external memory store, retrieved when needed.

```
[system prompt] + [history summary] + [last N turns in full] + [this turn's new messages]
```

**In one sentence**: **keep detail nearby, keep summaries far away, retrieve when necessary** — that is controllable memory management.
