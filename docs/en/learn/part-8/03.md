# Chapter 3: Integration and Pitfalls

> Each module is fine on its own, but assembled together it "will not run" — a stage every project goes through. This chapter covers **integration**: how to get it running end to end, how to diagnose, and how to tune.

---

## 3.1 Run a complete task end to end {#sec-1}

**In plain terms**: pick a **real but not complex** task, run it from start to finish, and see whether the whole chain works.

**Technical**: **end-to-end (E2E) testing** verifies the complete chain of "user sends an instruction → the system executes → a result is obtained." A suggested task:

> "Read all `.md` files under `data/` and summarize them into one `summary.md`."

**Key**: **use a real task, not a toy task** — toy tasks do not cover real problems.

---

## 3.2 Diagnosing common problems {#sec-2}

**In plain terms**: during integration, these are the most common ailments:

| Symptom | Common cause | How to check |
|---|---|---|
| model **does not call tools** | unclear tool description / not registered | check the tool list and the description |
| context **blows up** | no compaction / tool results too large | check token count, add compaction |
| permission **denied** | path out of bounds / permission level too low | check the audit log |
| **infinite loop** | no max steps set | add `MAX_STEPS` |
| result **wrong** | model picks the wrong tool / wrong arguments | check the trajectory and the schema |

**Key**: **look at the trajectory first** — it explains almost 80% of "the agent acting silly."

---

## 3.3 Performance and cost tuning {#sec-3}

**In plain terms**: once it runs, you must also ask "**is it fast, is it cheap**?"

**Technical**:

- **cost**: token consumption is the biggest item → compact context, trim tool results, use a cheaper model for simple work;
- **speed**: parallelize what can be parallelized, cache what can be cached, avoid repeated model calls;
- **reliability**: retry, timeout, fallback (Part 7).

**Key**: **"expensive" and "slow" often share a cause** — "context too long, calls too many." Fix that first.

- [ ] Can state the **three directions** for cutting cost and speeding up (compaction / parallel-cache / switch models).
