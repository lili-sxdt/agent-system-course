# Chapter 2: Implementing Module by Module

> The blueprint is drawn; construction begins. This chapter covers how to **implement piece by piece, module by module**, rather than "writing one giant file in one go."

---

## 2.1 Assemble block by block from Parts 1–6 {#sec-1}

**In plain terms**: each earlier part is a "prefabricated block"; now assemble them:

| From | Assembles into |
|---|---|
| Part 1 | core loop + context + model + tools |
| Part 2 | plugin container + config |
| Part 3 | skills / tools / personas |
| Part 4 | session / memory / sandbox / approval |
| Part 5 | subagents / workflows / orchestration |
| Part 6 | interface / service / frontend / CLI |

**Key**: **mount one block at a time and test right after.** Do not save everything for one big integration at the end — that is a "disaster scene."

---

## 2.2 Acceptance criteria per block and integration {#sec-2}

**In plain terms**: after each block is mounted, first verify "is this block right," then combine it with others.

**Technical**: each block needs **acceptance criteria** (how to know it is done) + an **interface contract** (how to connect with other blocks). **Define the interface first, then implement**, so integration does not descend into conflict.

```ts
// contract-first: define "what it looks like" first, then implement separately
interface ToolRunner {
  run(name: string, args: unknown): Promise<{ ok: boolean; data?: unknown; error?: string }>
}
```

**Key**: **contract-first is the premise of "multi-person / multi-module parallelism"** (remember Part 2 and "how to assign people"?).

---

## 2.3 How to locate a problem and roll back {#sec-3}

**In plain terms**: problems are certain during assembly. Do not force through them; **know how to locate and how to roll back.**

**Technical**:

- **locate**: check logs → check the trajectory → narrow the range (bisection: cut the system in half and see which half has the problem);
- **roll back**: when you break something, `git` back to the last good state; do not keep editing broken code;
- **commit in small steps**: commit after each block is done, so you can always revert.

**Key**: **"able to roll back" matters more than "never making mistakes"** — because you will make mistakes.
