# Chapter 4: Acceptance Checklist and Extension Directions

> The last step: **acceptance** — confirm that your mini-harness truly reaches the "publishable v0.1" threshold. Then, see where it can grow further.

---

## 4.1 Item-by-item acceptance (against the "7 publishability criteria") {#sec-1}

**In plain terms**: do not just say "I think it works." **Check one by one.**

| # | Criterion | Does your system pass? |
|---|---|---|
| 1 | **usable**: can reliably execute a complete task | ☐ |
| 2 | **installable**: others can install and run it | ☐ |
| 3 | **configurable**: adjustable via config/presets | ☐ |
| 4 | **documented**: has a README / examples | ☐ |
| 5 | **secure**: permission boundaries, sandbox, approval | ☐ |
| 6 | **reproducible**: tests + repeatable environment | ☐ |
| 7 | **maintainable**: versions, CHANGELOG, revertible | ☐ |

**Then check the five elements + pluggability**:

- [ ] context / model / tool / loop / persona — **all five present**;
- [ ] capabilities are **plug-in**, mountable and unmountable;
- [ ] there is a **security boundary** that is not crossed.

**Key**: **all checked = your v0.1 is real.** For any unchecked item, go back to the relevant part and fill it in.

---

## 4.2 What else can be added (extension directions) {#sec-2}

**In plain terms**: v0.1 is only the starting point. To make it stronger, you can add:

| Direction | Example |
|---|---|
| **multimodal** | let it see images and hear audio |
| **gateway / multi-model** | one entry point to several models, chosen automatically |
| **plugin marketplace** | let others share/install plugins |
| **stronger memory** | a long-term memory store + retrieval |
| **finer permissions** | grant precisely by operation type |

**Key**: **do not add everything at once** — go one by one by priority (remember "start simple, add complexity as needed"?).

---

## 4.3 Capstone summary and next steps {#sec-3}

**What you did from zero**:

- understood the agent's five elements and architecture;
- wrote the core loop, tools, skills, and personas by hand;
- built a mini-harness with memory, security, and pluggability;
- made it callable (interface / frontend / CLI) and acceptable (7 criteria).

**Next**: move into **Part 9** — **actually ship it**, collect feedback, verify, maintain, change, and re-release v0.2. **"Building it" is only half the journey; "shipping and iterating" is the complete engineering skill.**

---

## Checklist {#sec-4}

- [ ] Checked each of the **7 criteria** and knows which are not yet met.
- [ ] Confirmed **five elements + pluggability + security** are complete.
- [ ] Can name 2–3 **extension directions** and a priority rationale.
- [ ] Understands that "release + iterate" is the next step.
