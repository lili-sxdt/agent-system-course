# 第4章 工具与任务编排

> 多智能体/工作流一旦并行起来，就会冒出一堆工程问题：谁先跑、跑多久、失败了怎么办。这一章讲**编排**——让"一群 Agent"别乱套。

---

## 4.1 并发 / 超时 / 重试

**大白话**：三个保命机制：

- **并发控制**：别一口气开 100 个任务把机器压垮；
- **超时**：一个任务卡住太久，砍掉，别让它拖死全局；
- **重试**：偶发失败（网络抖动）自动重试几次，别一失败就放弃。

**专业**：

```ts
// 示意：并发上限 + 超时 + 重试
const limit = pLimit(4)                       // 最多 4 个并发
const task = () => withTimeout(work(), 30_000) // 30s 超时
await retry(task, { times: 3, backoff: 'exp' })// 最多重试 3 次，指数退避
```

**要点**：**重试要有上限 + 退避**，否则"疯狂重试"反而雪上加霜。

---

## 4.2 调度与优先级

**大白话**：活多了要排队，**重要的先干**。

**专业**：**调度（Scheduling）** 决定"谁先跑、跑几个、用多少资源"。**优先级**让紧急/关键的活插队。常见策略：FIFO、优先级队列、公平调度。

**要点**：**给关键任务留资源**，别让一堆小任务把大任务饿死。

---

## 4.3 任务跟踪（Jobs）与进度

**大白话**：一堆任务在跑，你得能**看见它们的状态**——谁在跑、谁完成、谁失败。

**专业**：**任务跟踪**给每个任务一个 ID 和状态（pending/running/done/failed），支持**查询进度、查看输出、取消任务**。这是"多任务系统"可观测性的基础。

```ts
interface Job {
  id: string
  status: 'pending' | 'running' | 'done' | 'failed' | 'killed'
  progress?: number
  output?: string
}
```

**要点**：**任务必须能被查、被停**——不然跑飞了你都不知道、也管不了。
