# 第3章 目标驱动循环（Goal）

> 普通循环"一步一停"，复杂任务要"跨很多步、跨很多轮、甚至跨很多天"。这一章讲**目标驱动循环**：让 Agent 朝着一个目标**持续自我推进**。

---

## 3.1 长任务的自我推进 {#sec-1}

**大白话**：有些活一次说不完、也做不完——比如"把这 30 篇文献精读完并写综述"。你需要给它**一个目标**，让它**自己一轮一轮往下推**，而不是每步都要你催。

**专业**：**目标驱动循环（Goal）** 是围绕一个**持久化目标**推进的执行机制。它记录"目标是什么、进度到哪、下一步做什么"，并在每轮结束时**自动判断是否继续**。

```ts
interface Goal {
  id: string
  objective: string      // 目标
  phase: 'active' | 'done' | 'blocked'
  rounds: number         // 已推进轮数
  maxRounds: number
}
```

**要点**：**目标要落盘**（持久化），这样即使中途中断，也能接着干。

---

## 3.2 完成 / 阻塞的判断 {#sec-2}

**大白话**：什么时候算"干完了"？什么时候算"卡住了"？

**专业**：

- **完成（complete）**：目标**真的达成**（有产物、能验收），而不是"看起来做了"。
- **阻塞（blocked）**：同一个障碍**连续多轮**都没解决，才判阻塞——不能一遇困难就喊"卡住了"。

| 状态 | 判据 |
|---|---|
| 完成 | 目标达成、有证据 |
| 阻塞 | 同一条件连续 N 轮未变 |
| 继续 | 还有可推进的工作 |

**关键**：**"完成"要以"目标达成"为准，不是以"我尽力了"为准。** 这一点在自动化系统里尤其重要。

---

## 3.3 断点续跑 / 记忆持久化 {#sec-3}

**大白话**：干到一半断了（关机、崩溃），下次**从断的地方接着干**，别从头再来。

**专业**：**断点续跑**靠"**持久化的进度**"实现：把目标状态、已完成步骤、中间产物写盘；恢复时读回，继续推进。**这和第四部分的"会话持久化"是一套思路**——只是粒度更粗（按轮/按阶段）。

```
[目标+进度落盘] → 中断 → 重启 → [读回进度] → 从断点继续
```
