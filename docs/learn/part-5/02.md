# 第2章 工作流（Workflow）

> 有些任务不是"一个循环"能搞定的，而是"**好几道工序串起来**"。这一章讲怎么把多步骤组织成**工作流**。

---

## 2.1 什么是工作流

**大白话**：工作流 = 把任务拆成**一道道工序**，按顺序（或并行）走完。像流水线：原料→加工→质检→包装。

**专业**：**Workflow** 是把任务编排成**多个阶段（stage）**的结构化流程，每个阶段可以是"一个 Agent 调用"或"一个工具调用"，阶段之间有明确的**输入输出契约**。

```
[阶段1: 检索] → [阶段2: 筛选] → [阶段3: 提取] → [阶段4: 汇总]
```

**要点**：工作流和"一个长循环"的区别是——**工作流的结构是你定的，循环的路径是模型自己走的**。

---

## 2.2 阶段与屏障

**大白话**：阶段之间有时要"等一等"——**等上一阶段都完成了，才能进下一阶段**。这个"等"叫屏障。

**专业**：**屏障（barrier）** 是阶段间的同步点。有屏障 → 所有并行任务完成才继续；无屏障 → 各自往下走（流水线，更快但更复杂）。

| | 有屏障 | 无屏障（流水线） |
|---|---|---|
| 特点 | 整齐、简单 | 快、但难管 |
| 适合 | 阶段强依赖 | 各任务独立 |

---

## 2.3 并行执行与结果合并

**大白话**：同一个阶段里，多个活可以**同时干**；干完把结果**汇总**。

**专业**：**并行执行**（parallel）提升吞吐；**结果合并**（reduce）把多份输出整合成一份。注意**部分失败**的处理——一个失败不该拖垮全部。

```ts
// 示意：并行 + 合并
const results = await parallel(tasks.map(t => () => runStage(t)))
const merged = results.filter(Boolean).flat()   // 过滤失败的，合并成功的
```

**要点**：**允许部分失败**，并**记录哪些失败了**——别让一个坏结果毁掉整批。

---

## 2.4 与"一个长循环"的取舍

**大白话**：能用简单循环搞定，就别上工作流。

| | 一个长循环 | 工作流 |
|---|---|---|
| 结构 | 模型自己决定 | 你预先定死 |
| 可控性 | 低 | 高 |
| 灵活 | 高 | 低 |
| 适合 | 探索性任务 | 固定流程 |

**经验法则**：**流程稳定 → 工作流；路径不确定 → 循环。** 别过度编排（对应 Anthropic 那句"先简单，按需加复杂度"）。
