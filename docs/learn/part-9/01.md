# 第1章 发布 v0.1

> 欢迎来到第九部分——**"发出去之后"**。前面你做出了 v0.1，但它还在你电脑上。这一章把它**真正发出去**，让别人也能用。

> 本部分会区分 **【课】可学的知识** 与 **【做】必须你亲自做的动作**。发布这件事，知识能教你，手感得你自己走一遍。

---

## 1.1 打包产物 {#sec-1}

**大白话**：先决定"你要发的是什么"——是一个能 `npm install` 的库？一个能双击运行的命令？还是一个安装包？

**专业**：**打包产物形态**：

| 形态 | 适合 |
|---|---|
| **库（library）** | 别人在代码里 `import` |
| **CLI 可执行** | 命令行直接用 |
| **安装包/容器** | 交付给非技术用户 |

关键配置（`package.json`）：

```jsonc
{
  "name": "my-agent",
  "version": "0.1.0",
  "bin": { "my-agent": "./dist/cli.js" },   // 命令入口
  "files": ["dist"],                         // 发布哪些文件
  "exports": { ".": "./dist/index.js" }      // 别人 import 什么
}
```

---

## 1.2 发布到仓库 {#sec-2}

> **【做】** 这一步必须你亲自执行——涉及你的账号与凭据。

**大白话**：把打包好的东西**传到 npm（或私有仓库）**，别人就能装了。

**专业**：

```bash
npm publish            # 发布到 npm
npm publish --access public   # 公开包（免费账号首次）
```

发布前建议先 `npm pack` 看一遍"要发出去的文件"对不对。

---

## 1.3 发布前自检 {#sec-3}

> **【课+做】** 清单能教你，但**真的在另一台机器上装一遍**，只能你做。

- [ ] 对照"可发布 7 标准"逐项验（第八部分 4.1）；
- [ ] `LICENSE` / `NOTICE` 合规（保留 MIT、写清与 DSH 的关系）；
- [ ] **跨环境真机验证**：另一台电脑、另一个系统、另一套 Node 版本。

> **【做】经验段**：真正的第一次发布，**总会有你没预料到的环境问题**——在你机器上好好的，别人那儿就报错。这只能靠真发一次才知道。

---

## 验收清单 {#sec-4}

- [ ] 能说清三种**打包产物形态**及各自适用场景。
- [ ] 知道 `bin` / `files` / `exports` 各管什么。
- [ ] 能执行一次 `npm publish`（或私有仓库发布）。
- [ ] 完成了**跨环境真机验证**。

**追问**（答不上来就回看 1.1）：为什么发布前要先 `npm pack` 看一眼，而不是直接 `npm publish`？
