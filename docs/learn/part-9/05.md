# 第5章 修改

> 要发 v0.2，就得改代码。但"改"是有讲究的——**改得对、改得稳、改得能退**。

---

## 5.1 定位问题

**大白话**：**先找到病根，再下药**。别凭感觉改。

**专业**：定位手段（第7部分 3.1）：

- **日志**：看错误发生的上下文；
- **轨迹**：看 Agent 每一步在干嘛（联调第一手段）；
- **二分**：把系统/代码砍一半，看问题在哪半。

**要点**：**先复现、再定位、最后改**——顺序别反。

---

## 5.2 小步修改与回滚

**大白话**：**一次只改一点**，改完测一下，能退就退。

**专业**：

- **小步提交**：每个改动独立提交，便于回退和定位；
- **分支 + PR**：改动在分支上做，评审后再合并；
- **可回滚**：任何改动都要能一键退回上一个好状态。

**要点**：**"能回滚"是安全网**——有了它，你才敢大胆改。

---

## 5.3 测试护航与质量门

**大白话**：改之前有测试兜底，改完跑全量，过了门才合。

**专业**：

- **改前**：确认相关测试存在（没有就补）；
- **改后**：跑**全量回归**，不只看你改的那块；
- **质量门**：lint / test / build 全过才允许合并。

> **【做】经验段**：**改一个地方引发另一个地方坏**——这只有被坑过，才知道"全量回归"有多重要。

---

## 5.4 可复现环境

**大白话**：保证"换个人也能重跑出一样结果"。

**专业**：环境快照 + 随机种子 + 锁定依赖（第7部分 2.2）。**改完之后，别人还能复现**，才叫改对了。

---

## 验收清单

- [ ] 能说出定位问题的**三种手段**及"先复现再改"的顺序。
- [ ] 坚持**小步提交 + 可回滚**。
- [ ] 知道改后要跑**全量回归**、过**质量门**。
- [ ] 能保证改动后**别人仍可复现**。

**追问**（答不上来就回看 5.3）：你只改了一个工具函数，为什么也要跑"全量回归"，而不只测这个函数？
