# 第7章 复盘与进入下一轮

> 最后一张。v0.2 发出去了，但故事没有结束——**发布后生命周期是一个持续循环**。这一章讲怎么复盘、怎么进入下一轮。

---

## 7.1 收集 v0.2 的反馈

**大白话**：新版本发出去，接着问两个问题：

1. **这版有没有解决问题**？（验证改动有效）
2. **有没有带来新问题**？（回归、兼容）

**专业**：对每个"进 v0.2"的改动，**验证它确实解决了原反馈**——别"改了但没解决"。

---

## 7.2 更新路线图与优先级

**大白话**：根据新反馈，重新排"下一版做什么"。

**专业**：

- 更新**路线图**（哪些进 v0.3、哪些砍）；
- 明确**维护承诺**（哪个版本长期支持）；
- 记录"**这次没做什么、为什么**"，避免反复讨论。

---

## 7.3 回到循环

**大白话**：然后，**再来一遍**：反馈 → 验证 → 维护 → 修改 → 再发布 v0.3……

**专业**：**发布后生命周期是持续闭环**，不是一次性任务。每转一圈，系统更稳、更贴合真实需求。

```
发布 → 反馈 → 验证 → 维护 → 修改 → 再发布 → （回到反馈）
  ↑___________________________________________|
```

> **【做】** 这个循环，**只有你真实地走上一两轮**，才能把"知识"变成"能力"。

---

## 全课收尾：你从零走到了哪里

- 你理解了 **Agent 五要素**与整体架构；
- 你亲手写出了**核心循环、工具、技能、人设**；
- 你搭出了有**记忆、安全、可插拔**的 mini-harness；
- 你让它**能被调用、能被验收、能被发布**；
- 你走完了**发布 → 反馈 → 验证 → 维护 → 修改 → 再发布**的完整生命周期。

**"能自己编写出来"——到此成立。**

## 最后一句诚实的话

课程能给你**知识和方法**（标【课】的部分，我尽力教全了）；
但**"真实地发一版、被人用、出问题、修掉、再发一版"**（标【做】的部分）——
**只能靠你自己走一遍**。再全的课程也给不了那份手感。

**去发你的 v0.1 吧。**
