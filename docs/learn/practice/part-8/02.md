# 例2 · 联调：让各部分对上

> 目标：各部分单独都对，**拼到一起却出错**——联调就是「在真环境里把接口一个个对上」。

## L1 接口对齐：先定「契约」 {#sec-1}

联调第一大坑是「各自以为对面长这样」。先定**契约**（共同约定），谁也别猜。

```ts
// contract.ts —— 双方共同依赖的唯一事实源
export interface ToolCall {
  name: string        // 工具名（必须一致）
  args: Record<string, unknown>
}
export interface ToolResult {
  content: string     // 返回给模型的文本
  isError?: boolean
}
```

> **契约放在共享文件里**，不要两边各写一份——两份迟早不一致。

## L2 真实场景跑一遍 {#sec-2}

单测是「理想输入」，联调是「真实乱输入」。重点测**边角**：

```ts
// 空输入、超长、特殊字符、缺字段
const cases = [ { args: {} }, { args: { path: '' } }, { args: 42 } ]
for (const c of cases) {
  const r = await route('tool.read', c)   // 看它会不会崩、会不会误报
  console.log(r)                          // 应当优雅失败，不抛异常
}
```

> **凡是要「读外部世界」的节点**（文件、网络、API），一定要测「它给你怪东西时你怎么办」。

## L3 端到端握手：一次完整运行 {#sec-3}

```
请求 ──►【编排】──►【工具】──►【模型】──►【输出】
                ▲                  │
                └── 工具结果回填 ──┘
```

跑一遍**真任务**，盯四个接缝：**①请求进来了吗；②工具被调用了吗；③结果回填了吗；④对模型输出了吗**。哪个缝断，问题就在哪。

## 变体练习（举一反三） {#sec-4}

1. **定义一个工具契约**，让「工具注册方」和「调用方」共用。
2. **给工具加「怪输入」防护**：缺字段、类型错误都优雅返回。
3. **跑一遍真任务**，指出哪个接缝最可能出问题。

## 通用套路：契约先行 + 真实输入 + 盯接缝 {#sec-5}

**联调三步**：①**契约先行**（共同类型，一份为准）；②**真实/怪输入**（理想输入测不出问题）；③**盯接缝**（请求→工具→回填→输出四个环节，定位断点）。**哪里要读外部世界，哪里就要重点联调**。
