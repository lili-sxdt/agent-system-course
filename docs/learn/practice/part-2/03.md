# 例3 · 生命周期与配置

> 目标：掌握插件的生命周期（加载/初始化/工作/卸载）与配置（默认 < 用户 < 预设）。

## L1 生命周期骨架 {#sec-1}

```ts
export function myPlugin(ctx: Context, config: MyConfig) {
  // 加载：注册能力
  ctx.tool(readFileTool)

  // 就绪：初始化
  ctx.on('ready', () => console.log('ready'))

  // 卸载：清理（很重要）
  ctx.on('dispose', () => console.log('cleaned up'))
}
```

> 四个阶段：load（注册）→ ready（初始化）→ running（工作）→ dispose（清理）。

## L2 用 dispose 清理资源 {#sec-2}

```ts
export function myPlugin(ctx: Context) {
  const timer = setInterval(() => {}, 1000)
  const conn = openConnection()

  ctx.on('dispose', () => {
    clearInterval(timer)     // ← 不清理，这个定时器会一直活着
    conn.close()
  })
}
```

> **新手最常犯的错**：只写启动、不写清理。反复装卸会漏资源，系统越来越慢甚至崩。

## L3 配置：默认 < 用户 < 预设 {#sec-3}

```ts
const defaultConfig = { enabled: true, pollMs: 5000 }

export function myPlugin(ctx: Context, config = defaultConfig) {
  const final = { ...defaultConfig, ...config }   // 默认值被用户配置覆盖
  console.log('pollMs:', final.pollMs)
}
```

> 优先级：**默认值 < 用户配置 < 预设/命令行**。越"临时/具体"的越优先。写回时注意**原子写**（先临时文件再替换）与**校验**（非法就给默认）。

## 变体练习（举一反三） {#sec-4}

1. **给插件加配置**：写一个插件，配置项 `interval`（默认 5000），卸载时清理定时器。
2. **优先级**：用户传 `{ pollMs: 1000 }`，预设在命令行覆盖成 `pollMs: 0`，最终应为多少？

## 通用套路：能装能卸 + 配置优先 {#sec-5}

**"卸" = 干净地卸**（清所有资源）；**配置**按"默认 < 用户 < 预设"合并，写回要校验 + 原子写。
