# 例1 · 给 Agent 写测试

> 目标：Agent 是"代码+工具+模型"组合，**每一层都要有测试兜底**——不然改一处、坏一片。

## L1 最小可测：纯函数先测 {#sec-1}

把"纯逻辑"抽出来，不碰 IO、不碰模型，先测它。

```ts
// format.ts —— 纯函数，无副作用
export function makePrompt(task: string, ctx: string) {
  return `任务：${task}\n上下文：${ctx}`
}

// format.test.ts
import { describe, it, expect } from 'vitest'
import { makePrompt } from './format'

it('拼出提示词', () => {
  expect(makePrompt('读README', '这是正文')).toContain('任务：读README')
})
```

> **为什么先测纯函数**：不依赖环境、随时能跑、跑得飞快。

## L2 工具层测试：mock 外部依赖 {#sec-2}

工具调用模型/读文件——外部依赖用 **mock** 顶替，只测"我家"的逻辑。

```ts
import { test, expect, vi } from 'vitest'
import { readTool } from './tools'

vi.mock('node:fs', () => ({
  readFileSync: vi.fn(() => '假数据')
}))

test('读取文件', () => {
  const r = readTool({ path: 'x.md' })
  expect(r).toContain('假数据')
})
```

## L3 端到端：整条链跑一遍 {#sec-3}

全链路（真实模型可换成 mock）跑一个最小任务，验证**能跑通**。

```ts
// agent.test.ts —— 集成测试
test('端到端：给定任务 → 返回结果', async () => {
  const result = await runAgent('一句话介绍你自己', { maxSteps: 3 })
  expect(result.length).toBeGreaterThan(0)
})
```

> **分层视角**：单元（快/准）→ 集成（工具+模型协同）→ 端到端（完整用户体验）。**越往后越慢、越贵**，所以平时跑单元，关键跑端到端。

## 变体练习（举一反三） {#sec-4}

1. **给工具层加"超时/失败"用例**：模型挂了会怎样？
2. **用 `vi.fn()` 统计调用次数**：确认某个工具被调了几次。
3. **加一条"断言用户目标达成"的端到端用例**。

## 通用套路：分层测试，靠边界隔离 {#sec-5}

**Agent 测试 = 单元（纯函数）+ 集成（mock 外部）+ 端到端（真实/替身模型）。** 关键是**边界清晰**：哪些是自己的逻辑（要测）、哪些是外部依赖（mock 掉）。**别把测试都堆成端到端**——慢且脆。
