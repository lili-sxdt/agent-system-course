# 例2 · 讲人话的日志

> 目标：日志是排查 Agent 问题的"黑匣子"。**要能回答"刚才发生了什么、错在哪一步"**，而不是一屏乱码。

## L1 带级别 + 带时间 {#sec-1}

```ts
export function log(level: 'info' | 'warn' | 'error', msg: string, meta?: object) {
  const line = `[${new Date().toISOString()}] [${level}] ${msg}`
  const extra = meta ? ` ${JSON.stringify(meta)}` : ''
  ;(level === 'error' ? console.error : console.log)(line + extra)
}

log('info', '工具已注册', { count: 3 })
// [2026-08-18T10:00:00.000Z] [info] 工具已注册 {"count":3}
```

> **分级**：`info` 讲流程、`warn` 提醒要警惕、`error` 只给真出错——**别把什么都打成 info**，否则出问题没人看得出。

## L2 结构化 = 能机器搜 {#sec-2}

打**结构化字段**，别只拼字符串——日志才能 grep、能进日志系统、能统计。

```ts
interface LogEntry {
  ts: string; level: string; event: string; sessionId: string; ms?: number
}

function emit(e: LogEntry) {
  console.log(JSON.stringify(e))
}

emit({ ts: now(), level: 'info', event: 'session.create', sessionId: 's-123' })
emit({ ts: now(), level: 'info', event: 'tool.call', sessionId: 's-123', ms: 42 })
```

> **关键字段**：`event`（事件名）、`sessionId`（关联到哪次会话）、`ms`（耗时）——**事件名用枚举，不写自由文本**。

## L3 可观测：请求ID + 耗时 + 成本 {#sec-3}

```
info  [trace=t-abc] session.create  session=s-1
info  [trace=t-abc] tool.read   path=a.md   ms=3
info  [trace=t-abc] llm.call    tokens=1200 cost=0.012  ms=850
warn  [trace=t-abc] model.retry attempt=1  reason=timeout
info  [trace=t-abc] session.done  steps=4 cost=0.05
```

> **一条链路一个 `trace`**，把一次 Agent 运行的所有事件串起来；token 与 cost 是**第二天最可能在意的数**。

## 变体练习（举一反三） {#sec-4}

1. **加一个 `warn` 用例**：模型超时重试时打一条。
2. **用 `sessionId` 过滤**：只看某次会话的日志。
3. **把 `log` 抽成可开关**：`--debug` 时输出更细。

## 通用套路：结构化 + 分级 + 一条 trace 串到底 {#sec-5}

**日志三要素**：①**分级**（info/warn/error）；②**结构化**（字段不用自由文本）；③**trace 串联**（一次运行一个 ID）。模板：先事件、再 agent、再时间；**能查到、能看懂、能定位**。
