# 例2 · 写一个读文件工具

> 目标：让 Agent 有"手"。从最小（L1）→ 加校验/错误（L2）→ 完整可测（L3），并用 N-D-P-H 套路。

> 📚 **先用主线打底**：这一练对应 **[主线 第1部分](/learn/part-1/01)**——建议先读主线概念，再动手做。

## L1 最小能跑（一个工具 = 四块） {#sec-1}

```ts
import { defineTool } from './tool'   // scaffold：见主线第3章 defineTool

export const readFileTool = defineTool({
  name: 'read_file',
  description: '读取指定路径的文件内容。',
  parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
  async handler({ path }) {
    const fs = await import('fs/promises')
    return { ok: true, content: await fs.readFile(path, 'utf8') }
  },
})
```

## L2 现实中：加校验 + 错误处理 {#sec-2}

> 工具不是"一定成功"——文件可能不存在、参数可能非法。**失败也要好好返回**，别崩。

```ts
export const readFileTool = defineTool({
  name: 'read_file',
  description: '读取指定路径文件内容；文件不存在返回错误。',
  parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
  async handler({ path }) {
    if (!path || typeof path !== 'string') {
      return { ok: false, error: '缺少有效的 path' }
    }
    try {
      const fs = await import('fs/promises')
      return { ok: true, content: await fs.readFile(path, 'utf8') }
    } catch (e: any) {
      return { ok: false, error: `read failed: ${e.message}` }
    }
  },
})
```

## L3 完整：给工具写测试（vitest） {#sec-3}

```ts
import { expect, test } from 'vitest'
import path from 'node:path'
import os from 'node:os'

test('正常目录：返回内容', async () => {
  const r = await readFileTool.handler({ path: 'README.md' })
  expect(r.ok).toBe(true)
  expect(typeof r.content).toBe('string')
})

test('不存在文件：返回错误而不抛', async () => {
  const r = await readFileTool.handler({ path: path.join(os.tmpdir(), 'no-such-' + Date.now()) })
  expect(r.ok).toBe(false)
  expect(typeof r.error).toBe('string')
})
```

## 变体练习（举一反三） {#sec-4}

照这个套路，写一个新工具：
1. **list_files**：列出某目录文件名（`fs.readdir`）。
2. **count_words**：统计一段文字的单词数。
要求：N-D-P-H 齐全 + 校验/错误 + 各写一个测试。

## 通用套路：N-D-P-H {#sec-5}

**N**ame（名字）→ **D**escription（何时用）→ **P**arameters（参数 schema）→ **H**andler（处理函数）。四块齐 = 一个工具。描述写清"何时用"，模型才会用对。
