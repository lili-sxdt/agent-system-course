# 例1 · 打包发布：从代码到可用

> 目标：别人能**一键装、一键跑**你的 Agent，而不是"下载源码自己折腾"。

## L1 一个入口，一键跑 {#sec-1}

下面是一个 `package.json`（让用户一条命令就能用，注意我们把它放在 JSON 代码块里，不要加注释）：

```json
{
  "name": "my-agent",
  "version": "0.3.0",
  "bin": { "my-agent": "./bin/my-agent.js" },
  "scripts": { "start": "node bin/my-agent.js" },
  "dependencies": { "openai": "^4.0.0" }
}
```

```bash
npm install -g my-agent   # 全局安装
my-agent "帮我看个文件"      # 直接当命令用
```

> **发布标准**：安装即用；**依赖声明清楚**；`bin`（命令入口）+ `scripts.start`（跑起来）都有。

## L2 发布产物：把「跑它要的」都带上 {#sec-2}

```
my-agent/
├── bin/my-agent.js     # 入口
├── dist/               # 编译出的 JS（若 TS）
├── skills/             # 内置技能
├── README.md           # 怎么装、怎么用
├── package.json        # 依赖与脚本
└── CHANGELOG.md        # 变更记录
```

> **发布物 = 用户跑起来需要的全部**。别指望用户去读你源码猜怎么装。README 要写「三步跑起来」。

## L3 发布到仓库 / npm {#sec-3}

```bash
npm publish     # 发布到 npm（若开源发布）
# 或发布到 GitHub，README 里写清安装方式
```

> **发布前自检**：`npm pack` 看发布物里**有没有多余的、缺没缺关键的**。**版本号 + CHANGELOG + tag** 三者一致再发。

## 变体练习（举一反三） {#sec-4}

1. **给项目加 `bin` 入口**，`npm install -g` 后能当命令用。
2. **写一段「三步跑起来」**的 README。
3. **`npm pack` 检查发布物**：有没有漏东西。

## 通用套路：一键装 + 发布物齐全 + 一致版本 {#sec-5}

**可发布的 Agent**：①**有命令入口/一键跑**；②**发布物带全**（依赖、技能、README）；③**版本号 + CHANGELOG + tag 一致**。**发布是「给别人用」，不是「自嗨」**——README 就是用户的第一眼。
