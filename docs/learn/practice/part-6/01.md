# 例1 · JSON-RPC 与 Web 服务

> 目标：把 Agent 变成"能被程序调"的服务——一个 HTTP 接口 + JSON-RPC 约定，并默认只监听本地。

<!-- 双向导航: 回主线 -->
> 📚 **先用主线打底**：这一练对应 **[主线 第6部分](/learn/part-6/01)**——建议先读主线概念，再动手做。

## L1 起一个 HTTP 服务 + 健康检查 {#sec-1}

```ts
import http from 'node:http'

const server = http.createServer((req, res) => {
  if (req.url === '/health') {
    res.writeHead(200, { 'Content-Type': 'application/json' })
    res.end(JSON.stringify({ ok: true }))
  }
})

server.listen(3080, '127.0.0.1', () => console.log('listening on 127.0.0.1:3080'))
```

> **要点**：监听端口 + `/health` 健康检查 + **默认绑 127.0.0.1（不对外网）**——安全默认。

## L2 JSON-RPC：请求/响应配对 {#sec-2}

```ts
// 请求
{ "jsonrpc": "2.0", "id": 1, "method": "session.send", "params": { "text": "你好" } }
// 响应
{ "jsonrpc": "2.0", "id": 1, "result": { "ok": true } }
```

> **`id` 让请求与响应配对**——并发多个请求不会串。

处理一个 JSON-RPC 请求：

```ts
async function handle(req: any) {
  const { id, method, params } = req
  try {
    const result = await route(method, params)
    return { jsonrpc: '2.0', id, result }
  } catch (e) {
    return { jsonrpc: '2.0', id, error: { code: -1, message: e.message } }
  }
}
```

## L3 SDK 分层：minimal / app / protocol {#sec-3}

| 层 | 作用 |
|---|---|
| `protocol` | 定义消息类型与契约 |
| `minimal` | 最精简客户端/服务端 |
| `app` | 高层封装（开箱即用） |

> **按需使用**：只连一下用 minimal；要完整能力用 app。

## 变体练习（举一反三） {#sec-4}

1. **加一个 `session.list` 方法**：返回会话列表，走 JSON-RPC。
2. **给服务加 CORS / 认证**：只允许本机访问的中间件。

## 通用套路：先定能力，再定接口 {#sec-5}

**能力决定接口**，不是反过来。对外暴露遵循**最小暴露**（只开必要方法，每个有明确权限）。默认监听本地，健康检查随时探测"活着没"。
