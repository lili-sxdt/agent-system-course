# 例3 · 命令行入口（CLI）

> 目标：让 Agent 在终端、脚本、流水线里都能用——一个**可执行命令**，能 `--help`、能 `--json`、能进 CI。

## L1 一个最小 CLI {#sec-1}

```js
// cli.ts
import { runAgent } from './agent'

const task = process.argv.slice(2).join(' ')   // 取命令参数
runAgent(task).then(console.log)
```

```bash
my-agent "读一下 README 的标题"     # 一行命令跑一个任务
```

## L2 子命令 + 参数 {#sec-2}

| 子命令 | 作用 |
|---|---|
| `run <task>` | 执行任务 |
| `session list/new/rm` | 管理会话 |
| `skill list/install` | 管理技能 |
| `config get/set` | 配置 |

> **参数原则**：`--help` 永远能用（自我说明）；默认值合理；错误提示清楚。

```bash
my-agent --help
my-agent config get port
my-agent run --json "整理数据"     # 输出可给程序读
```

## L3 进 CI：非交互 + 退出码 + 可解析 {#sec-3}

```ts
async function main() {
  try {
    const r = await runAgent(process.argv[2])
    console.log(JSON.stringify({ ok: true, result: r }))   // 可解析
    process.exit(0)                                        // 成功 → 0
  } catch (e) {
    console.error(JSON.stringify({ ok: false, error: e.message }))
    process.exit(1)                                        // 失败 → 非0
  }
}
// 非交互：绝不"卡住等输入"
```

> **能在 CI 里跑** = 从"人用"到"系统用"的分水岭。要求：退出码规范、非交互、输出可解析、可重入。

## 变体练习（举一反三） {#sec-4}

1. **加 `--help`**：列出子命令与用法。
2. **加 `--json`**：输出 JSON，便于脚本处理。

## 通用套路：CLI 要"人能用、程序能调" {#sec-5}

**CLI 是脚本化/自动化的入口**；输出既给人看（格式化）也给程序读（`--json`）；进 CI 要**非交互 + 退出码 + 可解析 + 可重入**。
