# 例2 · 工作流（阶段与屏障）

> 目标：把多步骤组织成**工作流**——每个阶段一个步骤，阶段之间用"屏障"同步。

<!-- 双向导航: 回主线 -->
> 📚 **先用主线打底**：这一练对应 **[主线 第5部分](/learn/part-5/01)**——建议先读主线概念，再动手做。

## L1 定义几个阶段 {#sec-1}

```ts
const stages = [
  { name: 'retrieve', run: () => searchTheWeb('主题') },
  { name: 'filter',   run: (r) => r.filter(x => x.relevant) },
  { name: 'summarize', run: (list) => summarizeAll(list) },
]
```

> **工作流 = 你预先定好结构**；每个阶段可以是"一次 Agent 调用"或"一个工具调用"，阶段间有**输入输出契约**。

## L2 顺序阶段：一个完成再下一个 {#sec-2}

```ts
async function runWorkflow(stages: any[]) {
  let data: any
  for (const s of stages) {
    data = await s.run(data)     // 有序执行；上一个完成才进下一个
  }
  return data
}
```

> **顺序执行最稳**：每个阶段的输入=上一阶段输出，出错也容易定位。**真正的"屏障"（等所有并行任务完成）在 L3**：那才有 `Promise.allSettled`。

## L3 并行 + 合并（允许部分失败） {#sec-3}

```ts
async function parallelStages(tasks: any[]) {
  const results = await Promise.allSettled(tasks.map((t) => t.run()))  // 允许部分失败
  return {
    ok: results.filter((r) => r.status === 'fulfilled').map((r: any) => r.value),
    failed: results.filter((r) => r.status === 'rejected').map((r: any) => r.reason),
  }
}
```

> **要点**：**允许部分失败**并**记录哪些失败**——别让一个坏结果毁掉整批。

## 变体练习（举一反三） {#sec-4}

1. **写一个"检索→摘要→写报告"工作流**：三个阶段，各自 run 函数。
2. **并行两个子阶段**：一个查"背景"、一个查"方法"，屏障后合并。

## 通用套路：工作流 vs 循环 {#sec-5}

**流程稳定 → 工作流**；**路径不确定 → 循环**。工作流结构你定、可控；循环路径模型自己走、灵活。别过度编排（先简单，按需加复杂度）。
