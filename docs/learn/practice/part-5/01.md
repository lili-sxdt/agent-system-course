# 例1 · 子代理（派活与收结果）

> 目标：把一个大任务**派给"分身"**，并**结构化回收**结果。关键是 spawn（全新上下文）+ 结果落盘。

<!-- 双向导航: 回主线 -->
> 📚 **先用主线打底**：这一练对应 **[主线 第5部分](/learn/part-5/01)**——建议先读主线概念，再动手做。

## L1 spawn 一个子代理 {#sec-1}

```ts
const result = await spawnSubagent({
  task: '检索近三年马铃薯氮素诊断的高光谱研究，输出 5 篇关键文献',
  schema: {
    papers: [{ title: 'string', doi: 'string', why: 'string' }],
  },
})
console.log(result.papers)
```

> **spawn = 全新上下文**，子代理不继承你的偏见；**审计/独立评估必须用 spawn**。

## L2 结构化回收 + 落盘 {#sec-2}

```ts
import fs from 'node:fs/promises'   // 结果要落盘，故引入

const result = await spawnSubagent({
  task: '读 data/*.md 并总结成摘要',
  schema: { summary: 'string', fileCount: 'number' },
})

// 1) 结果落盘（即使上下文丢了，成果还在）
await fs.writeFile('subagent-result.json', JSON.stringify(result, null, 2))
// 2) 返回结构化结果 + 产物路径，而非"讲一堆"
```

> **要点**：子代理结果要**结构化 + 落盘**；未落盘的信息标"【待办】"，避免"说做了、没留痕"。

## L3 fork vs spawn 的选择 {#sec-3}

```ts
// fork：继承父对话（需要共享背景时用）
const r1 = await forkSubagent({ task: '基于我们刚才讨论的，继续补充' })

// spawn：全新（独立、纯净、审计用）
const r2 = await spawnSubagent({ task: '独立评估以下结论是否有证据', schema: { verdict: 'string' } })
```

> 审计/独立评估**必须 spawn**——继承上下文的"审计"会带偏见，等于自审。

## 变体练习（举一反三） {#sec-4}

1. **并行派两个子代理**：一个查"方法"，一个查"数据"，`Promise.all` 等两者完成。
2. **给子代理 schema**：让它返回 `{ ok, findings }`，主 Agent 据此整合。

## 通用套路：子代理 = 独立上下文 + 结构化落盘 {#sec-5}

**子代理**的三个价值：隔离（不污染主上下文）/ 并行 / 分工。**spawn 全新、fork 继承**（审计用 spawn）；结果**结构化 + 落盘**，未落盘标【待办】。
