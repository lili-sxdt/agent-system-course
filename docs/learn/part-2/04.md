# 第4章 生命周期

> 插件不是"一装了事"。它有自己的**一生**：被加载 → 初始化 → 工作 → 卸载。这一章讲清楚这个过程，尤其是**新手最容易忽略的"清理"**。

---

## 4.1 插件何时加载 / 初始化 {#sec-1}

**大白话**：插件被装进容器后，容器会在合适的时机**叫醒它**："该你了，起来干活。"

**专业**：典型生命周期钩子：

| 阶段 | 干什么 | 类比 |
|---|---|---|
| 加载（load/apply） | 插件被注册、开始生效 | 入职报到 |
| 初始化（start/ready） | 建立连接、准备资源 | 打开电脑、连上网络 |
| 工作（running） | 响应事件、处理请求 | 正常上班 |
| 卸载（dispose） | 释放资源、断开连接 | 离职、交接 |

```ts
export function myPlugin(ctx: Context) {
  // 加载时：注册能力
  ctx.tool(readFileTool)

  // 就绪时：做初始化
  ctx.on('ready', () => {
    console.log('我的插件已就绪')
  })

  // 卸载时：清理（非常重要，见 4.3）
  ctx.on('dispose', () => {
    console.log('清理完成')
  })
}
```

---

## 4.2 顺序与依赖 {#sec-2}

**大白话**：有的插件"没它不行"——比如"工具"依赖"容器"先就绪。**顺序错了，就会在还没准备好时被调用，直接报错。**

**专业**：容器通过**依赖声明**决定加载顺序：A 声明依赖 B，则 B 先加载。这叫**依赖拓扑排序**。

```ts
// 示意：声明依赖，容器保证被依赖者先就绪
ctx.inject(['logger'], (ctx) => {
  ctx.logger.info('logger 已就绪，我才开始')
})
```

**要点**：**不要假设"我加载时，别人已经好了"。** 用依赖声明，让容器帮你排序。

---

## 4.3 卸载与清理 {#sec-3}

**大白话**：插件"下班"时要**把自己搞乱的东西收拾干净**——关掉定时器、断开连接、注销监听。不清理会**漏资源**，时间一长系统越来越慢、甚至崩。

**专业**：`dispose` 阶段要**释放所有持有资源**，避免内存泄漏、句柄泄漏、事件监听堆积。**"能装能卸"的"卸"，指的就是干净地卸。**

```ts
export function myPlugin(ctx: Context) {
  const timer = setInterval(() => {/* ... */}, 1000)

  ctx.on('dispose', () => {
    clearInterval(timer)   // ← 不清理，这个定时器会一直活着
  })
}
```

> **新手最常犯的错**：只写"启动"，不写"清理"。短期看不出问题，长期必出问题。
