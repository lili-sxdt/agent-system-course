# 第3章 注册思维

> 前两章讲了"要插件化、用容器管"。这一章教你**具体怎么和容器打交道**：把东西"注册"进去。掌握这几句，你就能给系统加能力了。

**核心心法一句话**：**别自己到处 new，而是"向容器登记"。**

---

## 3.1 ctx.plugin()：加入系统 {#sec-1}

**大白话**：把你写的插件**交给容器**，它就"入伙"了。

```ts
ctx.plugin(myPlugin)          // 装一个插件
ctx.plugin(myPlugin, options) // 装一个插件，并带上配置
```

**专业**：`ctx.plugin(fn, config?)` 把插件函数注册进容器，容器会按生命周期调用它，并把配置传进去。**这是插件与系统发生关系的第一句话。**

---

## 3.2 ctx.tool() / ctx.skill()：注册能力 {#sec-2}

**大白话**：你想给 Agent 加一个"能做的事"（工具）或"会讲的知识"（技能），就**登记到容器**，而不是塞进某个大文件。

```ts
ctx.tool(readFileTool)   // 注册一个工具：Agent 从此能调用它
ctx.skill(mySkill)       // 注册一个技能：Agent 需要时会读到它
```

**专业**：`ctx.tool()` / `ctx.skill()` 是"能力注册"的入口。注册后，系统在组装时会把它们**自动收集**到"可用工具/技能列表"，交给模型。**你只负责登记，收集与分发由容器完成。**

> 这就是为什么 DSH 里"写一个 SKILL.md 就能被加载"——本质就是**注册**。

---

## 3.3 ctx.on()：监听事件与钩子 {#sec-3}

**大白话**：系统会发生各种"事件"（加载完了、用户说话了、要卸载了……）。你可以**挂个钩子**："这事儿发生时，顺便做点我的事"。

```ts
ctx.on('ready', () => console.log('系统就绪，我的插件开始工作'))
ctx.on('dispose', () => console.log('系统要关了，我来收尾'))
```

**专业**：`ctx.on(event, handler)` 订阅事件。事件驱动让插件**解耦**——A 不用直接调用 B，只要 A 发事件、B 监听即可。

---

## 3.4 约定优于配置 {#sec-4}

**大白话**：别啥都让用户填。**能定好的默认值，就定好**；用户只改他真关心的。

**专业**：**约定优于配置（Convention over Configuration）**——用合理默认降低使用成本，只在必要时暴露配置项。DSH 的插件大多"装了就按约定工作，需要时才配"。
