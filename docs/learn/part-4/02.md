# 第2章 记忆与压缩（Compaction）

> 会话越来越长，上下文就越堆越多——直到塞不下、或者模型开始"看花眼"。这一章讲怎么给记忆**瘦身**。

---

## 2.1 上下文太长的代价 {#sec-1}

**大白话**：上下文不是越多越好。太长了有三个坏处：

1. **贵**：token 越多，钱越多；
2. **慢**：处理时间长；
3. **笨**：模型会"注意力涣散"——关键信息被淹没，反而记不住重点。

**专业**：上下文长度受**模型窗口上限**限制；即使没超，过长也会降低有效注意力（"lost in the middle"现象），并推高成本与延迟。

---

## 2.2 压缩策略：摘要与精简 {#sec-2}

**大白话**：把"啰嗦的历史"**总结成一段话**，或者**只留关键信息**，腾出空间。

**专业**：**压缩（Compaction）** 常用两招：

| 策略 | 做法 | 取舍 |
|---|---|---|
| **摘要** | 用模型把前 N 轮总结成一段 | 省空间，但可能丢细节 |
| **精简** | 删冗余、裁工具结果、去重复 | 保留结构，但要小心删错 |

```ts
// 示意：把较早的历史摘要成一条
const summary = await chat([
  { role: 'system', content: '把下面的对话压缩成不超过 200 字的关键信息。' },
  { role: 'user', content: oldMessages.map(m => `${m.role}: ${m.content}`).join('\n') },
])
messages = [{ role: 'system', content: `【历史摘要】${summary.content}` }, ...recentMessages]
```

**要点**：**压缩后要能"接着干"**——摘要得保留"任务目标、已完成、待办、关键结论"，别只留下寒暄。

---

## 2.3 记忆分层：最近 vs 长期 {#sec-3}

**大白话**：像人一样——**最近的事记得细，很久以前的事记要点**。

**专业**：**分层记忆**：
- **短期（近几轮）**：完整保留，保证连贯；
- **长期（更早）**：压缩成摘要或存入外部记忆库，需要时再检索回来。

```
[系统提示词] + [历史摘要] + [最近 N 轮完整] + [本轮新消息]
```

**一句话**：**近处保细节、远处留摘要、必要再检索**——这就是可控的记忆管理。
