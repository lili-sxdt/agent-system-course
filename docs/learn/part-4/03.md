# 第3章 文件系统 / 工作区（Workspace / FS）

> Agent 要干活，就得碰文件。但"碰文件"是**高风险动作**。这一章讲：怎么给 Agent 划定一个**安全的活动范围**，并设计好文件工具。

---

## 3.1 工作区：Agent 在哪个目录干活 {#sec-1}

**大白话**：别让 Agent 在整个硬盘上乱跑。给它**一个文件夹**当"办公室"，它就在这里面干活——这就是**工作区（Workspace）**。

**专业**：**工作区**是 Agent 被授权读写的**根目录**。所有文件操作都以它为基准解析路径，越界即拒绝。它既是"活动范围"，也是"安全边界"。

```ts
const WORKSPACE = process.env.DSH_PROJECT_DIR ?? process.cwd()
```

**要点**：**先定工作区，再谈文件操作**。没有边界，后面所有安全设计都无从谈起。

---

## 3.2 文件读写工具设计 {#sec-2}

**大白话**：给 Agent 几把"专用工具"——读、写、列目录、搜索、编辑。**每把工具都要能失败、能报错**（第3部分 2.2）。

**专业**：常见文件工具及其职责：

| 工具 | 作用 | 注意 |
|---|---|---|
| `read_file` | 读内容 | 大文件要分页/截断 |
| `write_file` | 写内容 | **原子写**（临时文件+替换） |
| `list_files` | 列目录 | 限制深度、忽略大目录 |
| `search` | 搜内容 | 正则/关键词，限制范围 |
| `edit` | 定点替换 | 精确匹配，避免误改 |

**要点**：**写入要原子**——先写临时文件再替换，避免"写一半崩了，文件损坏"。

---

## 3.3 路径安全：只碰该碰的 {#sec-3}

**大白话**：用户（或模型）可能传一个"想溜出去"的路径，比如 `../../Windows/System32`。**你必须拦住它。**

**专业**：**路径穿越（Path Traversal）** 是最常见的漏洞之一。防御方法：**把路径解析成绝对路径，再校验它是否落在工作区内**。

```ts
import path from 'node:path'

function safePath(workspace: string, userPath: string) {
  const abs = path.resolve(workspace, userPath)   // 解析成绝对路径
  const rel = path.relative(workspace, abs)        // 相对工作区
  if (rel.startsWith('..') || path.isAbsolute(rel)) {
    throw new Error('路径越界，拒绝访问')
  }
  return abs
}
```

**要点**：
- **别用字符串拼接**判断，要用 `path.resolve` + `path.relative`；
- **软链接**也可能绕出去，谨慎处理；
- **越界即拒绝**，不要"尽力而为"。
