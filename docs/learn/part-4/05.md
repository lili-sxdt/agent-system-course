# 第5章 审批与授权

> 沙箱和权限是"系统自动拦"。但有些操作**必须人来拍板**——这就是**审批**。它是安全的最后一道、也是最有弹性的一道防线。

---

## 5.1 关键操作让用户确认 {#sec-1}

**大白话**：遇到"可能出事"的操作，Agent 别自作主张，**先停下来问一句**："我要删这个文件，确定吗？"

**专业**：**审批（Approval）** 是在敏感操作执行前，暂停流程、请求用户确认的机制。确认后再执行，拒绝则中止并告知模型。

```
模型想删文件 → 命中"需审批"规则 → 暂停 → 问用户 → 同意则删 / 拒绝则告知模型
```

**要点**：审批要**信息充分**——把"要做什么、影响什么"说清楚，用户才好判断。

---

## 5.2 敏感操作清单与放行规则 {#sec-2}

**大白话**：不能啥都问（烦），也不能啥都不问（险）。列一张**敏感操作清单**，命中才问。

**专业**：典型需审批的操作：

| 类别 | 例子 |
|---|---|
| **破坏性文件操作** | 删除、覆盖、批量移动 |
| **执行任意命令** | shell 命令、脚本 |
| **网络外发** | 上传文件、发请求带敏感数据 |
| **越界访问** | 工作区外的路径 |
| **花大钱** | 大量 token 调用、批量任务 |

**放行规则**可分级：
- **总是允许**（读工作区文件）；
- **总是询问**（删除、执行命令）；
- **永不自动**（访问密钥、系统目录）。

---

## 5.3 审计可追溯 {#sec-3}

**大白话**：出了事要能查——**谁、在什么时候、让 Agent 做了什么**。

**专业**：**审计日志（Audit Log）** 记录每次敏感操作：时间、操作类型、参数、批准者、结果。它既是安全追溯，也是"复盘改进"的依据。

```jsonl
{"ts":"2026-09-08T16:13","op":"delete_file","arg":"old.csv","approved":true}
```

**要点**：审计日志**本身不能包含密钥**；要能**防篡改**（至少只追加、不覆盖）。

---

## 验收清单 {#sec-4}

- [ ] 能说清**审批**的作用（敏感操作前暂停、请求确认）。
- [ ] 能列出**至少四类**需要审批的操作。
- [ ] 能说出**放行规则的分级**（总是允许 / 总是询问 / 永不自动）。
- [ ] 能说出审计日志要记什么、以及"不能含密钥"。

**追问**（答不上来就回看 5.2）：如果每个操作都弹窗问用户，会有什么问题？该怎么平衡"安全"和"烦人"？

---

## 第四部分小结 {#sec-5}

到这里，你的 mini-harness 从"能跑"升级到了"**敢用**"：有会话、有记忆管理、有安全边界、有审批与审计。**这正是"玩具级"和"能用级"的分界线。** 下一部分，我们从"一个 Agent"走向"一群 Agent"：多智能体与编排。
