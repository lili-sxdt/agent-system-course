# 第4章 验收清单与扩展方向

> 最后一步：**验收**——确认你的 mini-harness 真的达到了"可发布 v0.1"的门槛。然后，看看它还能往哪长。

---

## 4.1 逐项验收（对照"可发布 7 标准"） {#sec-1}

**大白话**：别只说"我觉得能用了"。**一条条对**。

| # | 标准 | 你的系统过了吗 |
|---|---|---|
| 1 | **能用**：能稳定执行一个完整任务 | ☐ |
| 2 | **能装**：别人能装起来跑 | ☐ |
| 3 | **能配**：可通过配置/预设调整 | ☐ |
| 4 | **能说明**：有 README / 示例 | ☐ |
| 5 | **能安全**：权限边界、沙箱、审批 | ☐ |
| 6 | **能复现**：测试 + 环境可重复 | ☐ |
| 7 | **能维护**：版本、CHANGELOG、可回退 | ☐ |

**再对照五要素 + 可插拔**：

- [ ] 上下文 / 模型 / 工具 / 循环 / 人设，**五要素齐全**；
- [ ] 功能**插件化**，能装能卸；
- [ ] 有**安全边界**，不越界。

**要点**：**全打勾 = 你的 v0.1 成立了。** 有没打勾的，回对应部分补。

---

## 4.2 还能加什么（扩展方向） {#sec-2}

**大白话**：v0.1 只是起点。想让它更强，可以加：

| 方向 | 例子 |
|---|---|
| **多模态** | 让它能看图、听音频 |
| **网关/多模型** | 一个入口接多家模型，自动选 |
| **插件市场** | 让别人能分享/安装插件 |
| **更强的记忆** | 长期记忆库 + 检索 |
| **更细的权限** | 按操作类型精细授权 |

**要点**：**别一次全加**——按需求优先级，一个一个来（还记得"先简单、按需加复杂度"吗）。

---

## 4.3 结课总结与下一步 {#sec-3}

**你从零做到了什么**：

- 理解了 Agent 五要素与架构；
- 亲手写出了核心循环、工具、技能、人设；
- 搭出了有记忆、有安全、可插拔的 mini-harness；
- 让它能被调用（接口/前端/CLI）、能被验收（7 标准）。

**下一步**：进入**第九部分**——把它**真正发出去**，收反馈、验证、维护、改、再发布 v0.2。**"做出来"只是半程，"发出去并迭代"才是完整的工程师能力。**
