# 第2章 分模块实现

> 图纸画好了，开始施工。这一章讲怎么**按模块一块块实现**，而不是"一口气写个巨型文件"。

---

## 2.1 按第一~六部分逐块组装

**大白话**：前面每个部分都是一块"预制件"，现在把它们装起来：

| 来自 | 装成什么 |
|---|---|
| 第1部分 | 核心循环 + 上下文 + 模型 + 工具 |
| 第2部分 | 插件容器 + 配置 |
| 第3部分 | 技能 / 工具 / 人设 |
| 第4部分 | 会话 / 记忆 / 沙箱 / 审批 |
| 第5部分 | 子代理 / 工作流 / 编排 |
| 第6部分 | 接口 / 服务 / 前端 / CLI |

**要点**：**一次只装一块、装完就测**。别攒到最后一起联调——那是"灾难现场"。

---

## 2.2 每块验收标准与联调

**大白话**：每块装完，先自己验一遍"这块对不对"，再和别的块拼。

**专业**：每块要有**验收标准**（怎么算这块做完了）+ **接口契约**（怎么和别的块对接）。**先定接口、再实现**，联调时才不打架。

```ts
// 接口契约先行：先定"长什么样"，再各自实现
interface ToolRunner {
  run(name: string, args: unknown): Promise<{ ok: boolean; data?: unknown; error?: string }>
}
```

**要点**：**契约先行**是"多人/多模块并行"的前提（还记得第2部分和"怎么安排人"吗）。

---

## 2.3 遇坑怎么定位、怎么回退

**大白话**：装的过程中一定会出问题。别硬扛，要**会定位、会回退**。

**专业**：

- **定位**：看日志 → 看轨迹 → 缩小范围（二分：把系统砍一半，看问题在哪半）；
- **回退**：改坏了就 `git` 回退到上一个好状态，别在坏代码上继续改；
- **小步提交**：每装好一块就提交一次，随时能退。

**要点**：**"能回退"比"不犯错"更重要**——因为一定会犯错。
