# 第3章 联调与踩坑

> 各模块单独都 OK，拼在一起却"跑不通"——这是每个项目都会经历的阶段。这一章讲**联调**：怎么端到端跑通、怎么排查、怎么调优。

---

## 3.1 端到端跑通一个完整任务

**大白话**：选一个**真实但不复杂**的任务，从头跑到尾，看整条链能不能走通。

**专业**：**端到端测试（E2E）** 验证"用户发指令 → 系统执行 → 得到结果"的完整链路。建议任务：

> "读 `data/` 下所有 `.md` 文件，汇总成一份 `summary.md`。"

**要点**：**用真实任务、不用玩具任务**——玩具任务盖不住真实问题。

---

## 3.2 常见问题排查

**大白话**：联调时最常见这几类毛病：

| 症状 | 常见原因 | 怎么查 |
|---|---|---|
| 模型**不调工具** | 工具描述不清 / 没注册 | 看工具清单、看描述 |
| 上下文**爆炸** | 没压缩 / 工具结果太大 | 看 token 数、加压缩 |
| 权限**被拒** | 路径越界 / 权限级别低 | 看审计日志 |
| **死循环** | 没设最大步数 | 加 `MAX_STEPS` |
| 结果**不对** | 模型选错工具 / 参数错 | 看轨迹、看 schema |

**要点**：**先看轨迹**——它几乎能解释 80% 的"Agent 犯傻"。

---

## 3.3 性能与成本调优

**大白话**：能跑之后，还要问"**快不快、贵不贵**"。

**专业**：

- **成本**：token 消耗是大头 → 压缩上下文、裁剪工具结果、便宜的模型干简单活；
- **速度**：并行能并的、缓存能缓的、别重复调模型；
- **可靠性**：重试、超时、降级（第七部分）。

**要点**：**"贵"和"慢"往往同源**——都是"上下文太长、调用太多"。先治这个。
