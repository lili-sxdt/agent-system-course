# 第4章 核心循环（Agent Loop）—— 它的工作方式

> 这是**全书最核心的一章**。前面备好了记忆（上下文）、脑子（模型）、手（工具）；这一章把它们转起来。看懂并写出这个循环，你就真正跨过了"聊天机器人 → Agent"的门槛。

---

## 4.1 循环的完整流程 {#sec-1}

**大白话**：Agent 干活的方式，就是**反复问自己四句话**：

```
① 现在该想什么？        → 把上下文交给模型
② 它想用哪个工具？      → 模型给出"调用意图"（或直接回答）
③ 工具做完了吗？结果是？ → 你的程序真的执行，拿到结果
④ 把结果塞回去，再想。  → 结果加进上下文，回到 ①
```

一直转到模型说"我想好了，不用工具了"，就收尾。这条链路叫 **Agent Loop（智能体循环）**。

![Agent 核心循环](../../assets/agent-loop.svg)

每一步在代码里对应哪一段：

| 步骤 | 代码动作 |
|---|---|
| ① 想 | 调 Provider 的 `chat(messages)` |
| ② 要工具 | 检查返回里有没有 `tool_calls` |
| ③ 做 | 执行对应工具的 `handler` |
| ④ 塞回去 | 把工具结果作为一条消息 append 到 `messages`，进入下一轮 |

---

## 4.2 模型怎么决定"用哪个工具" {#sec-2}

**大白话**：你不用教它"什么时候用"——你只要**把工具清单（名字+描述+参数）给它**，它自己会判断"这步需要读文件"，然后点名要 `read_file`。

**专业**：模型返回的响应里，`tool_calls` 字段是一个数组，每项包含**工具名**和**参数**：

```json
{
  "role": "assistant",
  "tool_calls": [
    { "id": "call_1", "function": { "name": "read_file", "arguments": "{\"path\":\"config.json\"}" } }
  ]
}
```

### 4.2.1 解析工具调用意图

```ts
const msg = await chat(messages, { tools: toolList })
if (msg.tool_calls?.length) {
  for (const call of msg.tool_calls) {
    const args = JSON.parse(call.function.arguments)
    const result = await runTool(call.function.name, args)   // 见 4.2.2
    messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(result) })
  }
} else {
  return msg.content   // 没有工具调用 → 收尾，直接给答案
}
```

### 4.2.2 执行并回填结果

**要点**：执行工具**一定要兜住错误**（第3章 3.3）。工具失败时把 `{ ok:false, error }` 作为结果回填，让模型据此调整，而不是让程序崩。

**还要控长度**：工具结果（比如"读一个大文件"）回填前应设**长度上限**并截断/摘要，否则一次调用就可能把上下文撑爆（见第四部分第2章）。

### 4.2.3 继续转 or 收尾

- 模型**还想要工具**（`tool_calls` 非空）→ 继续下一轮；
- 模型**不再要工具**（给出最终文字）→ 收尾返回。

---

## 4.3 循环何时终止 {#sec-3}

新手最怕"死循环"。三种终止条件都要有：

### 4.3.1 达成目标

模型给出最终回复、不再请求工具——**正常收尾**。

### 4.3.2 超步 / 超时

设一个**最大轮数**（如 20 步）和**单步超时**，到了就停，避免无限转。**这是保命机制，必须有。**

```ts
const MAX_STEPS = 20
for (let step = 0; step < MAX_STEPS; step++) {
  // ...一轮循环...
}
```

### 4.3.3 出错兜底

- 模型接口报错 → 重试或返回错误；
- 工具反复失败 → 提示模型"换个办法"或直接停；
- 参数解析失败 → 把错误回填给模型，让它重发。

---

## 验收清单 {#sec-4}

- [ ] 能背出循环的**四步**（想→要工具→做→塞回去）。
- [ ] 能说清"模型**不执行**工具，它只输出**调用意图**"。
- [ ] 能写出**解析 `tool_calls` → 执行 → 回填**的核心代码骨架。
- [ ] 知道循环**至少要有哪三种终止条件**，并会设 `MAX_STEPS`。

**追问**（答不上来就回看 4.3.2）：如果模型陷入"反复读同一个文件"的死循环，你靠什么机制把它拉出来？
