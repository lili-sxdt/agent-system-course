# 第5章 跑通第一个 Agent（整合）

> 收官一章。我们把第1~4章的东西——上下文、模型、工具、循环——**串成一个能跑的程序**。跑通它，你就真正拥有一个"裸 Agent"了。

---

## 5.1 端到端组装

**大白话**：前面是零件，现在是装机。把四块拼起来：

```
messages（上下文） → chat()（模型） → 有 tool_calls？（循环） → runTool()（工具） → 回填 → 再想
```

它能做的第一件实事：**读文件、按你的指令回答**。

## 5.2 观察它的轨迹

**大白话**：Agent 出问题时，光看最终答案是没用的——你要看它**每一步在干嘛**。

**专业**：打印**轨迹（trajectory）**：每一轮里"模型说了什么 / 想调哪个工具 / 参数是什么 / 结果是什么"。轨迹是你调试 Agent 的"行车记录仪"。

```ts
console.log(`[step ${step}] 模型:`, msg.content ?? `调用 ${msg.tool_calls?.[0]?.function.name}`)
```

学会看轨迹，你就能判断：它是**走弯路**、**选错工具**，还是**该停没停**。

## 5.3 最小可运行完整代码

把下面这段凑齐（工具定义见第3章），就是一个能跑的裸 Agent：

```ts
// agent.ts —— 最小可用 Agent：上下文 + 模型 + 工具 + 循环
type Msg = any
const MAX_STEPS = 20

// 1) 工具：一个读文件工具（简化版，完整版见第3章）
const tools = [{
  name: 'read_file',
  description: '读取指定路径的文件内容',
  parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
}]

async function runTool(name: string, args: any) {
  if (name === 'read_file') {
    try {
      const fs = await import('fs/promises')
      return { ok: true, content: await fs.readFile(args.path, 'utf8') }
    } catch (e: any) {
      return { ok: false, error: e.message }
    }
  }
  return { ok: false, error: `未知工具：${name}` }
}

// 2) 模型调用（Provider，见第2章）
async function chat(messages: Msg[]) {
  const res = await fetch(`${process.env.LLM_BASE_URL}/chat/completions`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${process.env.LLM_API_KEY}` },
    body: JSON.stringify({ model: 'deepseek-chat', messages, tools, temperature: 0.3 }),
  })
  return (await res.json()).choices[0].message
}

// 3) 核心循环（见第4章）
async function runAgent(userTask: string) {
  const messages: Msg[] = [
    { role: 'system', content: '你是一个助手，需要文件内容时用 read_file 工具读取。' },
    { role: 'user', content: userTask },
  ]

  for (let step = 0; step < MAX_STEPS; step++) {
    const msg = await chat(messages)
    messages.push(msg)
    console.log(`[step ${step}]`, msg.tool_calls ? `调用 ${msg.tool_calls[0].function.name}` : '最终回复')

    if (!msg.tool_calls?.length) return msg.content      // 收尾

    for (const call of msg.tool_calls) {
      const args = JSON.parse(call.function.arguments)
      const result = await runTool(call.function.name, args)
      messages.push({ role: 'tool', tool_call_id: call.id, content: JSON.stringify(result) })
    }
  }
  return '（达到最大步数，已停止）'
}

// 4) 跑一个真实任务
runAgent('读一下当前目录下的 package.json，告诉我项目名字叫什么。').then(console.log)
```

**一个测试任务 + 预期表现**：

- 任务：*"读一下 package.json，告诉我项目名字。"*
- 预期轨迹：`[step 0] 调用 read_file` → `[step 1] 最终回复：项目名是 xxx`。

## 你刚从零写出了什么

你写出的是一个**裸 Agent**：它能**看上下文、用模型、调工具、循环推进**。这就是 mini-harness 的**第一块骨头**。

> 注意它现在还很"裸"：没有记忆持久化、没有安全沙箱、没有插件化、不能发布。这些是后面第2、4、7、9部分的事——但**最核心的那条循环，你已经亲手搭出来了。**
