# 第1章 上下文（Context）—— 它的记忆

> 本章你将搞懂：模型每一轮到底"看到"了什么、上下文是怎么拼出来的、系统提示词怎么写，以及新手最常犯的两个错。这是"地基"的第一块砖。

第〇部分讲了 Agent 的**五要素**，第一个就是"上下文"。这一章我们把它拆开、看清楚。

---

## 1.1 什么是上下文 {#sec-1}

**大白话**：把模型想象成一个**每次都被蒙上眼睛、只给你看一叠纸**的人。它每一轮只能看你**这次递给它的那叠纸**——你写的话、它上一轮回的话、工具返回的结果、最上面那张"规矩"。这叠纸，就是**上下文**。

**专业**：上下文（Context）= 一次模型调用时，作为输入传给模型的**全部消息序列**。模型**没有记忆**——它对"之前发生过什么"的全部认知，都来自你这次传进去的这叠纸。

### 1.1.1 模型每一轮"看到"什么

一次调用里，模型看到的内容大致是：

- **system**：规则 / 人设（"你是谁、要守什么规矩"）；
- **历史消息**：user 和 assistant 交替的过往对话；
- **工具结果**：上一轮调工具后回填的内容（如读到的文件内容）。

### 1.1.2 上下文 = 所有可见信息的总和

记住这个公式：

```
上下文 = 系统提示词 + 历史对话 + 工具结果（+ 附件/文件片段等）
```

**你想让模型"知道"什么，就得把它放进这个公式里。** 没放进去的，模型一概不知。

### 1.1.3 例子：没有上下文为什么失忆

假设你每次都**只把当前这一句话**发给模型：

> 第一轮你说："帮我读一下 config.json。"
> 第二轮你说："改成 8080。"

如果第二轮你**没带上第一轮的对话**，模型会一脸茫然："改什么？改哪？"——不是它笨，是**你把它的记忆抽走了**。

**所以"记住"的本质不是模型记住，而是"你每次都把该带的都带上"。** 这句话很关键，后面讲"压缩"时还会用到。

## 1.2 系统提示词（System Prompt） {#sec-2}

### 1.2.1 作用：定人设、定规则、定边界

系统提示词是放在**最前面、每轮都在**的那段话，负责告诉模型：

- **人设**：你是"科研助手"还是"客服"；
- **规则**：回答要简洁 / 要先确认再动手；
- **边界**：哪些不能做（如"不要编造数据"）。

### 1.2.2 怎么写得清晰、具体、可执行

三条经验：

1. **具体**：别写"好好回答"，写"用不超过 3 句话回答"。
2. **可执行**：写成模型能照做的动作，而不是抽象态度。
3. **给例子**：关键格式给一两个"输入→期望输出"的样例。

### 1.2.3 它 vs 用户消息的区别

**大白话**：**系统提示词是老板定的规矩**（一直挂着、优先级高）；**用户消息是这次的具体要求**。规矩不该被一次要求轻易推翻。

**专业**：多数模型对 system 的遵循优先级高于 user。因此**关键约束放 system**，临时要求放 user。

## 1.3 消息结构（多轮） {#sec-3}

### 1.3.1 三种角色：user / assistant / system

| 角色 | 谁说的 | 作用 |
|---|---|---|
| `system` | 你（开发者） | 定规矩、人设 |
| `user` | 用户 | 提要求 |
| `assistant` | 模型 | 模型的回复（含工具调用意图） |

### 1.3.2 多轮如何拼成一条请求

一轮完整请求的 `messages` 大致长这样：

```ts
const messages = [
  { role: 'system', content: '你是一个严谨的助手，不确定就说不确定。' },
  { role: 'user', content: '帮我读一下 config.json 里的端口。' },
  { role: 'assistant', content: '好的，我来读。' },        // 上一轮模型的话
  { role: 'user', content: '读到了吗？' },                  // 这次用户的话
]
```

**要点**：历史消息**按时间顺序**排列，system 永远在最前。

### 1.3.3 常见错误

- **顺序错**：把 system 放到后面，或历史消息乱序 → 模型理解混乱。
- **角色混用**：把用户的话标成 assistant，或把模型的话标成 user → 模型分不清谁说的。
- **忘了带历史**：多轮任务里只发当前一句 → 模型"失忆"。

## 验收清单 {#sec-4}

- [ ] 能用一句话解释"模型为什么没有记忆、上下文是什么"。
- [ ] 能写出上下文的公式（system + 历史 + 工具结果）。
- [ ] 能说清 **system 和 user 的区别**，并知道关键约束该放哪。
- [ ] 能写出一个顺序正确的多轮 `messages` 数组。

**追问**（答不上来就回看 1.1.3）：模型"记住"了上一轮，是因为它真的有记忆，还是因为你把上一轮又发给它了？这对你设计 Agent 意味着什么？
