# 第2章 工具（Tool）

> 技能是"会讲的知识"，工具是"能做的动作"。这一章把第一部分第3章（认识工具）的"三要素"升级成**可注册、可维护、可测试**的工程写法。

---

## 2.1 defineTool：怎么定义一个工具

**大白话**：一个工具 = **名称 + 描述 + 参数 + 处理函数**（还记得 N-D-P-H 吗）。用 `defineTool` 把它包成一个规范对象，系统就能登记、模型就能调用。

```ts
import { defineTool } from './tool'

export const listFilesTool = defineTool({
  name: 'list_files',
  description: '列出指定目录下的文件名。当需要知道某个文件夹里有哪些文件时使用。',
  parameters: {
    type: 'object',
    properties: { dir: { type: 'string', description: '目录路径' } },
    required: ['dir'],
  },
  async handler({ dir }) {
    const fs = await import('fs/promises')
    try {
      return { ok: true, files: await fs.readdir(dir) }
    } catch (e: any) {
      return { ok: false, error: e.message }
    }
  },
})
```

---

## 2.2 入参 / 出参 / 描述规范

**入参**：用 JSON Schema 声明类型、必填、含义。**每个参数都要有 `description`**——模型靠它填对值。

**出参**：**统一结构**，推荐 `{ ok: boolean, ... }`：成功带数据，失败带 `error`。**统一结构让模型更容易理解结果、也让你的循环更好处理。**

**描述**：一句话说清"**能干嘛 + 什么时候用**"。别只写"读取文件"，要写"读取指定文件内容，当你需要查看某个文件时使用"。

---

## 2.3 描述怎么写模型才"会用对"

这是最容易忽视、却最影响效果的一点：

- **写清"何时用"**：模型靠它判断该不该调。
- **写清"不要何时用"**（必要时）：避免误用。
- **别写内部实现**：模型不关心你用什么库，只关心"输入什么、得到什么"。

> **反例**：`description: "处理数据"` —— 模型完全不知道什么时候该用。
> **正例**：`description: "把 CSV 文件读取为表格数据，当用户要求分析表格文件时使用。"`

---

## 2.4 工具 vs 技能的分工

| | 工具（Tool） | 技能（Skill） |
|---|---|---|
| 本质 | **能做**的动作 | **会讲**的知识 |
| 例子 | 读文件、跑命令 | "怎么写周报" |
| 何时用 | 模型判断要执行 | 模型判断要参考 |
| 形态 | 代码 + schema | Markdown |

**一句话**：**工具负责"动手"，技能负责"指导怎么动手"。** 两者配合，Agent 才既有手、又有脑子里的"经验"。

---

## 2.5 一个工具的完整示例 + 测试

好工具要**能测**。给工具写个最小测试：

```ts
// 测试（vitest）：正常与异常路径都返回统一结构
import { expect, test } from 'vitest'
import path from 'node:path'
import os from 'node:os'

test('正常目录：返回文件列表', async () => {
  const r = await listFilesTool.handler({ dir: '.' })
  expect(r.ok).toBe(true)
  expect(Array.isArray(r.files)).toBe(true)
})

test('不存在的目录：返回错误而不抛异常', async () => {
  const missing = path.join(os.tmpdir(), 'no-such-dir-' + Date.now())
  const r = await listFilesTool.handler({ dir: missing })
  expect(r.ok).toBe(false)
  expect(typeof r.error).toBe('string')
})
```

**要点**：**工具失败也要"好好返回"**，而不是抛异常崩掉——第一部分第4章的循环才能稳稳接住。
