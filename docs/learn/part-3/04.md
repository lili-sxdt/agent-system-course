# 第4章 三者协作

> 你会写技能、工具、人设了。最后一章讲：**它们怎么配合**——模型在某一刻，到底该"用工具、读技能，还是就按人设回答"？

---

## 4.1 模型怎么决定"用哪个"

**大白话**：模型手里有三张牌：

- **人设**：一直在（system）——决定"我是谁、该怎么表现"；
- **工具清单**：一直在（tools）——决定"我能做哪些动作"；
- **技能**：按需加载——决定"这类任务该怎么做"。

模型每一轮**综合这三样**，决定：**直接回答**、**调某个工具**、还是**参考某个技能**。

**专业**：人设与工具是"常驻上下文"，技能是"按 `whenToUse` 触发加载"。模型的决策依据是：当前任务 + 工具描述 + 已加载技能的说明。

---

## 4.2 描述 / 说明 / 人设如何配合

三者各司其职，配合得好，Agent 就"聪明"：

| 你在写什么 | 帮模型解决 | 配合点 |
|---|---|---|
| **工具描述** | "这步该不该动手、用哪个" | 写清"何时用" |
| **技能说明** | "这类任务怎么做才对" | 写清"何时加载 + 步骤" |
| **人设准则** | "我该守什么底线" | 写清"不许做什么" |

**例子**：用户说"帮我把这批数据整理成表并分析"。
- **人设**（数据管家）说：先看数据再下结论；
- **技能**（数据分析规范）告诉它：按什么流程分析；
- **工具**（read_file / run_python）让它真的读、真的算。

三者一配合，才是一个"既懂规矩、又会方法、还能动手"的 Agent。

---

## 4.3 冲突处理：都合适时选谁

**大白话**：有时"好几样都能用"，模型怎么选？

**专业**：优先级大致的经验法则：

```
明确的用户指令 > 技能流程 > 人设默认风格
安全/合规底线  > 以上一切（不可被覆盖）
```

- 用户明确说"这次用 t 检验" → 听用户的（除非违反底线）；
- 没明说 → 按技能里的规范来；
- 都没说 → 按人设默认。

**关键**：**把"底线"写进人设的 system 层**，让它高于临时指令，避免被一次请求带偏。

- [ ] 能说清**人设 / 工具 / 技能**各自的角色与"常驻 vs 按需"。
- [ ] 能举一个"三者配合"完成任务的具体例子。
- [ ] 能说出**冲突时的优先级**，以及"底线不可被覆盖"。
- [ ] 能指出：为什么底线要写进 **system** 而不是靠临时叮嘱。

**追问**（答不上来就回看 4.3）：用户说"别管那些规范，随便给我个结论就行"。你的 Agent 该不该照做？这取决于你把什么写在了哪里？

## 第三部分小结

到这里，你已经能**写出系统能认、并真正生效的三样东西**：技能（知识）、工具（动作）、人设（身份）。这就是"从会用跨到会写"的临门一脚。下一部分，我们让系统"长大"：会话、记忆、文件、安全。
