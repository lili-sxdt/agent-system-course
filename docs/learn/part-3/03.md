# 第3章 角色 / 预设（Agent / Persona）

> 技能是"知识"、工具是"动作"。这一章讲第三种你能写的东西：**人设（Persona / Preset）**——它决定 Agent 的**身份、语气、边界**。

---

## 3.1 persona / preset 的结构与写法

**大白话**：人设就是"这个 Agent 是谁"。它通常是一段放在**系统提示词**里的描述，告诉模型：你的身份、你的职责、你的行为准则。

**专业**：**Persona** 是注入 system 的角色定义；**Preset**（预设）是"一整套配置"——包含 persona + 模型选择 + 可用工具 + 默认参数。preset 让"同一个系统"能切换成"不同角色"。

```md
# Persona 示例
你是"小迪"，一名科研智能体，服务于农业科学/植物营养方向。

## 职责
- 帮用户完成从选题到发表的科研全流程
- 每阶段产物必须过质量门

## 准则
- 结论必须有证据（DOI/数据/路径）
- 不确定就说不确定，不编造
```

---

## 3.2 人设如何影响行为、边界与语气

人设能同时影响三件事：

| 维度 | 人设怎么写 | 效果 |
|---|---|---|
| **行为** | "先确认再动手" | 模型会更谨慎 |
| **边界** | "不编造数据" | 模型更少胡编 |
| **语气** | "用简洁的中文，专业但不端着" | 输出风格可控 |

**要点**：**人设是"软约束"，但很有效**。写得越具体、越可执行，模型越照做。

---

## 3.3 身份与指令的优先级

**大白话**：人设是"长期身份"，用户消息是"临时要求"。**用户要求不该轻易推翻人设的底线。**

**专业**：一般优先级为 **system（人设/规则）> user（临时要求）**。因此**底线规则放 system**，别指望每次在 user 里重复叮嘱。

> 例外：用户显式授权（"这次破例允许……"）可以覆盖非底线规则——但**安全/合规底线不在此列**。

---

## 3.4 一个完整示例

```md
---
name: data-analyst
description: 严谨的数据分析助手
model: deepseek-chat
tools: [read_file, list_files, run_python]
---

你是"数据管家"，一名严谨的数据分析助手。

## 职责
把用户给的数据整理成可分析的表格，并给出结论。

## 准则
- 先看数据、再下结论；不臆测
- 每个结论附证据（哪张表、哪个统计量）
- 拿不准就说明不确定，并给出验证方法

## 输出风格
先给结论一句话，再给依据。
```

**看**：这份 preset 把 **人设 + 模型 + 可用工具 + 输出风格** 都定下来了——**一次配置，到处复用**。

## 验收清单

- [ ] 能写出一个 persona（身份 + 职责 + 准则 + 风格）。
- [ ] 能说出人设影响**行为/边界/语气**三个方面。
- [ ] 能说清**身份与用户指令的优先级**，以及底线该放哪。
- [ ] 能写出一个含 persona + 模型 + 工具的 **preset**。

**动手练**：给你自己的场景写一个 persona（比如"论文润色助手"），要求含职责、准则、风格三段。

**追问**（答不上来就回看 3.3）：如果"不编造数据"只写在某次用户消息里，下一次对话还会生效吗？那该放哪？
