# 第2章 服务化

> 让 Agent 从"一个程序"变成"一个服务"——别人（前端、脚本、别的系统）能通过网络连上它。

---

## 2.1 起一个 Web 服务

**大白话**：把 Agent 跑成一个"网站后台"，它在某个端口上**等着别人来连**。

**专业**：用 HTTP 服务暴露接口。要点：

- **监听端口**（如 `127.0.0.1:3080`）；
- **健康检查**（`/health` 返回 ok），方便"是否活着"被探测；
- **只监听本地**（`127.0.0.1`）而不是 `0.0.0.0`——**默认不对外网开放**，这是安全默认。

```ts
server.listen(3080, '127.0.0.1', () => console.log('listening on 127.0.0.1:3080'))
```

**要点**：**默认绑本地回环**，要对外必须显式配置——**安全的默认值很重要**。

---

## 2.2 WebSocket：前后端实时通信

**大白话**：HTTP 是"你问我答"，一问一答。但 Agent 干活是**流式**的（一个字一个字往外蹦、工具一步步跑）。这时需要一条**一直开着的双向通道**——WebSocket。

**专业**：**WebSocket** 建立后保持长连接，服务端可**主动推送**（如流式输出、工具进度）。适合实时交互场景。

```
[前端] ←WebSocket→ [Agent 服务]  （实时推送 token、工具状态）
```

**要点**：**流式输出**用 WebSocket；简单的一次性请求用 HTTP 就行，别过度设计。

---

## 2.3 客户端连接 / 心跳 / 复用

**大白话**：连接会断、会多、会重复——要管好。

**专业**：

- **心跳**：定期发个小消息，确认连接还活着，断了能及时发现；
- **复用**：同一个客户端别重复建连接；
- **重连**：断了自动重连，别让用户手动刷新。

**要点**：**连接是"活物"**，会掉、会抖——要有心跳和重连，不能假设它一直在。
