# 第3章 前端

> 服务起来了，但总不能让用户对着黑屏敲命令。这一章讲怎么给 Agent 做一个**能用、看得懂**的界面。

---

## 3.1 最小聊天界面

**大白话**：最简界面就三样：**输入框**（打字）、**消息区**（显示对话）、**发送按钮**。别一上来就搞花活。

**专业**：一个最小可用前端 = **消息列表 + 输入 + 发送 + 流式渲染**。技术栈随意（React/Vue/原生都行），关键是**能连上后端、能实时显示**。

**要点**：**先能聊，再谈好看。** 界面是"壳"，核心能力在后端。

---

## 3.2 会话列表 / 消息流 / 技能面板

**大白话**：能聊之后，加三个"看得见系统"的东西：

| 组件 | 作用 |
|---|---|
| **会话列表** | 左边一列，切换/新建/删除会话 |
| **消息流** | 中间主体，按时间显示对话 |
| **技能/工具面板** | 显示当前有哪些技能、工具，能开关 |

**专业**：这些组件把"系统状态"暴露给用户，让 Agent 从"黑盒"变成"**可观察、可控制**"的工具。

**要点**：**让用户看得见"系统在用什么能力"**——这直接影响信任感。

---

## 3.3 工具结果与轨迹可视化

**大白话**：Agent 调了工具、走了几步，用户往往一头雾水。**把它每一步显示出来**——调了什么工具、参数是什么、结果是什么。

**专业**：**轨迹（trajectory）可视化**：把工具调用折叠成"卡片"（可展开看参数/结果），把思考步骤按顺序展示。这是**调试**和**建立信任**的关键。

```
▶ 调用 read_file(path: "config.json")
  ✓ 返回: { "port": 8080 }
▶ 调用 run_python(...)
  ✓ 返回: 分析完成
```

**要点**：**默认折叠、需要时展开**——既不过度干扰，又能随时查证。
