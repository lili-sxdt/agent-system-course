# 第2章 测试与可复现

> 一个系统能不能被信任，很大程度上看两点：**测试够不够**、**结果能不能复现**。这一章讲这两件事。

---

## 2.1 单元 / 集成测试 {#sec-1}

**大白话**：

- **单元测试**：测"一个小零件"（如某个工具函数）对不对；
- **集成测试**：测"几个零件拼起来"对不对（如"读文件→分析→写结果"整条链）。

**专业**：

| | 单元测试 | 集成测试 |
|---|---|---|
| 范围 | 单个函数/模块 | 多模块协作 |
| 速度 | 快 | 慢 |
| 目的 | 逻辑正确 | 接口/流程正确 |

**要点**：**测试要能自动跑、能快速跑**。跑不动的测试 = 没有测试。

```ts
test('read_file 返回文件内容', async () => {
  const r = await readFileTool.handler({ path: 'fixture.txt' })
  expect(r.ok).toBe(true)
})
```

---

## 2.2 随机种子 / 环境快照 / 数据快照 {#sec-2}

**大白话**：同样的操作，昨天和今天结果不一样——那就没法查问题。要**把"变量"固定下来**。

**专业**：

- **随机种子（seed）**：把随机固定，让"每次跑都一样"；
- **环境快照**：记录依赖版本、系统信息（`package.json` + `package-lock.json`、Node 版本 `.nvmrc`）；
- **数据快照**：用固定的一份数据，别用"随时会变"的实时数据。

**要点**：**可复现 = 同输入 + 同环境 → 同输出。** 任何一环不固定，就复现不了。

---

## 2.3 复现报告 {#sec-3}

**大白话**：写一份"**别人照着能重跑出同样结果**"的说明。

**专业**：**复现报告（REPRODUCE.md）** 应包含：数据来源、脚本、命令、依赖版本、随机种子、产物清单 + 复现核查清单。

```md
## 复现步骤
1. 装依赖：npm ci
2. 跑：npm run reproduce
3. 产物在 results/，与 expected/ 对比
```

**要点**：**"别人能重跑"才是可复现**，不是"我这儿能跑"。
