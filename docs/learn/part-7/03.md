# 第3章 日志、监控、错误处理

> 系统上了线，出了问题怎么办？这一章讲"**看得见、扛得住**"——日志、监控、错误处理。

---

## 3.1 日志分级与尾随跟踪 {#sec-1}

**大白话**：程序要"记日记"。但不是什么都记——**重要的多记，琐碎的可关**。

**专业**：**日志分级**：

| 级别 | 用途 |
|---|---|
| `debug` | 调试细节（平时关） |
| `info` | 正常里程碑（启动、完成任务） |
| `warn` | 潜在问题（可恢复） |
| `error` | 出错了（需关注） |

**尾随跟踪（tail）**：实时看最新日志，边跑边看，排查问题时最有用。

**要点**：**日志要能"追"**（实时看），也要能**按级别过滤**（别被 debug 淹没）。

---

## 3.2 错误处理与降级 {#sec-2}

**大白话**：出错不可怕，**可怕的是崩了还不知道为啥**。要"接住错误、说清原因、能继续就继续"。

**专业**：

- **捕获**：别让异常直接崩掉整个系统；
- **分类**：可重试的（网络）vs 不可重试的（参数错）；
- **降级**：主路径失败时，退到"能用但差点"的方案（如换模型、跳过非关键步骤）；
- **上报**：把错误记进日志/监控。

```ts
try {
  return await primaryPath()
} catch (e) {
  log.warn('主路径失败，降级到备用', e)
  return await fallbackPath()
}
```

**要点**：**降级是"优雅地退让"，不是"假装没事"**——要记录、要能追溯。

---

## 3.3 监控：里程碑 / 健康状态 {#sec-3}

**大白话**：你得随时知道"系统活着没、干得怎么样"。

**专业**：**监控**关注两类：

- **健康状态**：进程活着吗、端口通吗、依赖可用吗（健康检查）；
- **里程碑**：关键事件（任务开始/完成/失败、模型调用次数、token 消耗）。

**要点**：**没有监控 = 出问题靠用户投诉**。有监控才能主动发现。
