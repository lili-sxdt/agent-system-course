# 第4章 学习地图与最终目标

> 这章给你一张"地图"：我们到底要做出什么、怎么一步步走到那，以及每条路大概多难。**先看图再上路**，不容易迷路。

---

## 4.1 你要亲手搭的"mini-harness"长什么样 {#sec-1}

我们的最终目标，不是"用别人做好的 Agent"，而是**亲手搭一个小的、自己的 Agent 运行时**。我们叫它 **mini-harness**。

它不只是"能跑个例子"那么简单，它有**边界**——它要像 DSH 那样：

- **可插拔**：功能拆成能装上/卸下的单元；
- **有工具**：模型能调用（读文件、跑命令等）；
- **有记忆**：能记住多轮对话、会压缩太长上下文；
- **安全可控**：知道哪些操作要用户确认、不乱动你的文件；
- **能发布**：能够打包、发给别人用，还能迭代一个版本。

一句话：**你最终交付的，是一个"能跑、敢用、还能发出去"的小 Agent 系统。**

## 4.2 各章如何一步一步把它拼出来 {#sec-2}

我们按"从底到上"的顺序，一点一点拼：

| 阶段 | 你在搭什么 | 对应部分 |
|---|---|---|
| ① 地基 | 上下文 + 模型 + 工具 + 循环（最核心的那条"想→做→看→再想"） | 第1部分 |
| ② 骨架 | 插件化 + 容器 + 配置（让它"有条理、可插拔"） | 第2部分 |
| ③ 能力 | 写自己的 Skill / 工具 / 人设 | 第3部分 |
| ④ 长大 | 会话/记忆/文件/安全/审批 | 第4部分 |
| ⑤ 编排 | 多智能体/工作流/目标循环 | 第5部分 |
| ⑥ 产品化 | 接口/服务/前端/命令行 | 第6部分 |
| ⑦ 工程化 | 结构/测试/日志/版本/规范 | 第7部分 |
| ⑧ 结课 | 把这些拼成一个完整的 mini-harness | 第8部分 |
| ⑨ 发布后 | 发出去 → 收反馈 → 验证 → 维护 → 改 → 再发布 | 第9部分 |

**关键**：每一步都是**在之前的基础上加一块**，最后第8部分只是"组装"，不是"从零再来"。

## 4.3 难度曲线 {#sec-3}

- **前期简单**（第0–1部分）：概念 + 最小可跑，很快能看到东西动起来。
- **第3部分是分水岭**：开始"真的写能被系统认出来的东西"（skill/工具/人设），这里最容易卡，但最有收获。
- **后期是深度**：安全、编排、产品化、工程化——需要一点系统与工程底子。

**一句话**：前面越做越有信心，中段"会写"是跨坎，后面是"让它专业"。**别怕中段——那正是别人和我都最想帮你跨过去的地方。**
