# 第2章 什么是 Harness / Agent 壳

> 上一章讲了 Agent 是"会动手的执行者"。但光有模型和工具还不够——**谁**负责把"模型"和"工具"和"记忆"拼在一起转起来？这就要引入本章的主角：**Harness（壳）**。

---

## 2.1 Harness 解决的核心问题 {#sec-1}

**大白话**：模型只是一颗"大脑"，但它自己不知道"什么时候该调工具、怎么把上一步结果递给下一步、怎么把一整段对话记住"。你需要在它周围**搭一个工作台**——这个工作台负责调度模型、接工具、记上下文、把结果呈现给你。**这个工作台，就是 Harness。**

**专业**：Harness（也常叫 Agent 框架 / Agent 运行时 / Agent Loop）负责编排"**上下文 → LLM → 工具 → 结果 → 回到上下文**"这个闭环，并处理会话、记忆、权限、错误、超时等外围杂事。简单说：**模型负责"想"，Harness 负责"让想变成做"。**

它能帮你处理的"杂活"包括：
- 决定**何时**该把工具结果喂回给模型；
- 记住**多轮对话**（上下文管理）；
- 失败时**怎么兜底**、超时怎么停；
- 哪些操作**要用户确认**、哪些能做（权限）。

---

## 2.2 DSH（DeepSeek Harness）是什么 {#sec-2}

**DSH** = DeepSeek（一家做大模型的公司）开源的、一个**插件化**的 Agent 运行时。它就干上面说的那些"壳的活"，而且做得非常彻底：

- 每一个功能都做成一个**可插拔的包**（`dsh-*`），你可以装、卸、替换；
- 内部用一套**插件容器**（Cordis）把它们串起来——这就是它塞了几百个模块却不乱的原因；
- 还给了你一套"**你怎么写自己的 skill / 工具 / 人设**"的规范，让你能扩展它。

**大白话**：DSH 像一个**已经打好架子、还带标准接口**的"Agent 工作台"。你要做的不必是重造它，而是**看懂它是怎么搭的**。

---

## 2.3 壳（Shell）与内核（Kernel）的区别 {#sec-3}

这两个词容易混，先分清：

- **内核（Kernel）**：**真正跑 agent 循环、调模型的核心引擎**——那套"想→做→看→再想"的逻辑就在这。它是"发动机"。
- **壳（Shell）**：**外层界面/程序**——负责把内核启动起来、展示对话界面、提供"打开设置/托盘/版本"这些人类可点击的东西。它是"车身 + 仪表盘"。

**大白话**：**内核是发动机，壳是车身和仪表盘。** 发动机决定"车怎么跑"，车身让人"能开、能看"。DSH 的内核就是那套循环引擎；你装的那个桌面程序（dsh-desktop）就是壳——它负责显示、启动、托盘、界面，真正干活的是内核。

> 我们这门课主要盯的是**内核（Harness）怎么搭**；壳（桌面/界面）是另一层，稍作了解即可。

> **体感一下**（先看懂，不急着做）：Harness 就是那个"让模型把想变成做"的工作台。同一个循环，Harness 会在你无感的情况下替你处理这些"杂活"：
>
> ```
> 你输入 → Harness 拼好上下文 → 交给模型
>        ← 模型要工具 → Harness 替你找到工具、执行、把结果塞回上下文
>        → 模型再想 → 循环，直到它觉得"做完了" → 呈现给你
> ```
>
> 你只管下指令，**"什么时候该喂结果、怎么记住多轮、失败怎么兜底"都由 Harness 接手**——这正是它存在的意义。后面第2部分你会亲手搭一个能装能卸的小壳。
