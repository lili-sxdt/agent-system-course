# 附录 D · 差异化作证

> 你基于 DSH（MIT 许可）学习、并自己做出了一个 Agent 系统。这一页讲两件事：**怎么合规**、**怎么证明它不只是"换皮"**。

## 一、先守住合规底线（MIT）

DSH 全部 222 个 `dsh-*` 包都是 **MIT 许可（Copyright © 2026 DeepSeek）**。MIT 允许使用、修改、分发、商用，但要求：

> **在"所有副本或实质性部分"中，保留版权声明与许可文本。**

**你要做的**：

- [ ] 仓库里放 `LICENSE`（含 MIT 全文 + DeepSeek 版权声明）；
- [ ] 加 `NOTICE`，写清"**哪些来自 DSH、哪些是你新写的**"；
- [ ] 复用了 DSH 代码的地方，注明来源；
- [ ] 若只"学了思想、自己从零写"，也要在 README 说明"受 DSH 启发"。

**别做**：把 DSH 改个名字/皮肤就宣称"完全原创"。

## 二、什么才算"新系统"（差异化作证）

| 维度 | 需要证明什么 | 怎么留证据 |
|---|---|---|
| **目标** | 它解决 DSH 不解决/不好的问题 | README 写清定位与差异 |
| **架构** | 核心抽象/设计有真变化 | 架构图 + 设计决策记录 |
| **骨架** | 是否脱离 Cordis/Cosmokit | 依赖清单（自己实现容器/循环）或明确标注"基于 DSH 扩展" |
| **能力** | 至少一个 DSH 没有的能力 | 该能力的代码 + 示例 + 对比 |
| **发布物** | 有自己的包名/版本/文档/测试 | 仓库结构 + CHANGELOG |
| **可复现** | 关键部分是你重写/原创 | 提交历史 + 复现报告 |

## 三、一份可用的 `NOTICE` 模板

```text
本软件包含来自 DeepSeek Harness 的代码（MIT License, Copyright © 2026 DeepSeek）。
原项目：https://github.com/deepseek-ai/deepseek-harness

以下部分为原创/改写：
- <模块 A>：独立实现，未使用原项目代码
- <模块 B>：改写自原项目 <包名>，已保留原许可声明

详见 LICENSE 与各源文件头部声明。
```

## 四、诚实的一句话

**"基于开源做衍生"完全正当，关键是把关系说清楚。** 想宣称"独立新系统"，就得在**目标 / 架构 / 骨架 / 能力**上有真差异，并如实标注来源。

> ⚠️ 涉及商用、专利、知识产权归属的最终定论，请核对 DSH 的 `LICENSE` 原文，必要时咨询专业人士。
